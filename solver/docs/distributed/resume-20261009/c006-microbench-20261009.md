## 固定した条件

- VOIDLINUX-2（192.168.0.22）、8物理コア・16論理CPU。CPU affinityは全0〜15。各実行の内部スレッド16、solver seed 0、`--mode parallel`。
- `PROCON37_G007_FUTURE_WEIGHT=0`、`PROCON37_G007_RESERVE_WEIGHT=15`。GPUは不使用。CPU設定は測定前後ともperformance。
- 公開 `generate_for_players(seed, None, 4)` によりseed 0/1/2を生成。形式自動、練習場取り込み既定有効。相手の実プロセスはありません。
- 既存通信テストと同じJSONL形式。各プロセスは100msのselectで既存の短時間fallbackを使い、全車種を「先頭の1台だけ補給車」に固定。このselectは車種選択の性能測定に含めません。
- 続いて同一の初日状態・10,000msのplan要求を1回だけ実行。当日採用案の公開engineによる合法性・初日得点を検証。
- 順序はseed 0がD0→C006、seed 1がC006→D0、seed 2がD0→C006。各要求20秒の応答タイムアウト、全体180秒の上限を設定。処理終了時に子プロセスを回収。

保存済みD0実行ファイルと、新しいローカルtoolchainでビルドしたC006実行ファイルの比較です。ビルド時点が異なるため、探索量の差を2行の変更だけに厳密に帰属させる測定ではありません。3台の分散通信、車種選択の探索、全日数、他チームとの相互作用、正式制限時間も今回の範囲外です。

## 再現方法

既存の結果を上書きしない新しいディレクトリをVOIDLINUX-2のホーム配下に作り、上記配置から `bin/`、`inputs/`、`run.py` をコピーします。作業場所の絶対パスは `run.py` が自身の位置から解決します。

```sh
# VOIDLINUX-2で実行。新しいIDを指定し、保存済み結果と分離する。
bench_id=c006-micro-repeat-001
bench_root="$HOME/procon37-distributed-resume/$bench_id"
test ! -e "$bench_root" && mkdir -p "$bench_root"
cp -a "$HOME/procon37-distributed-resume/c006-micro-20261009/bin" "$bench_root/"
cp -a "$HOME/procon37-distributed-resume/c006-micro-20261009/inputs" "$bench_root/"
cp "$HOME/procon37-distributed-resume/c006-micro-20261009/run.py" "$bench_root/"
cd "$bench_root"
sha256sum bin/d0 bin/c006
# 既存探索プロセスの競合がないことを確認して開始する。
timeout --signal=INT --kill-after=5s 180s python3 run.py
```

ローカルで公開engineの検証を再現するには、実際のリポジトリ位置を取得し、付属 `public_engine_helper.rs` を一時Rust workspaceの `src/main.rs` に置きます。依存は `tester = { path = "<実際のrepo>/solver/distributed/common" }` と `serde_json = "=1.0.151"`、edition 2024です。`helper validate inputs/seed-N.jsonl results/<実行ラベル>/stdout.jsonl` で、当該提出の受理と得点を出力できます。
