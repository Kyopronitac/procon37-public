保存済みの12件×2回の成績と公開リプレイを分析した。両方とも全48 AC。ソルバや固定相手の内部実装は参照していない。分析の読取・集計処理はローカルCPU 3に固定し、SSH・ビルド・追加実験・配置変更は行っていない。

- D0: `1791557693555197384-34655`
- C012: `1791558686429216196-38666`
- 各10秒、同じ4チーム、seed 0〜11、現行H2環境。両runの各seedのリプレイ内problemは完全一致。
- 元ファイルのSHA-256、全seedの全チーム得点、日別イベント集計は同名JSONに保存。

## 順位が改善しても玉数が+4に留まる理由

平均順位はD0 **1.6667 → C012 1.2500**（順位合計20→15）だが、種類数222・日別種類数1277は同じ、玉数2961→2965（+4）である。自己得点の比較は**6勝0同点6敗**。増加した6件で+19玉、減少した6件で−15玉が相殺した。

順位改善の大半は16盤面の6順位分で、24盤面が1順位分改善し、32盤面は2順位分悪化した。seed 0/4/6では自分の玉が減っていても順位は2位→1位になった。seed 0では固定並列の日別種類数が57→55となり、自分の56より下に変化した。seed 9は自分が97→99玉、固定相手が100/100/100→97/98/99玉となり、4位→同率1位の3順位分を占める。

固定相手の実行ファイル・設定を固定していても、得点が固定されるわけではない。時間制探索の変動に加え、全チームの経路から生じる翌日の共有混雑も異なる。本分析ではこの2要因の寄与を分離できない。したがって「順位改善すべてが日中通信の純粋な探索改善」「固定相手の乱数だけで生じた」のどちらも断定しない。

参考として保存済みの自己得点だけC012に入れ替え、D0回の相手得点と単純に並べ直すと順位合計20→19（平均1.5833）となる。逆に自己得点D0＋C012回の相手得点では21。この計算は順位の相対性を示すだけで、異なる混雑状態の得点を組み合わせるため仮想対戦や因果効果を再現していない。実際のC012順位合計15の改善が自己得点+4だけから自動的に導かれるわけではない、という留保に用いる。

### 車種・混雑・終端状態が同一ではない

- 自分の車種配列はD0 `[0,1,0,0,0,0,0]`、C012 `[0,0,0,1,0,0,0]`。補給役の初期位置が異なるため、単に同一の探索へ通信だけを足した経路比較にはならない。車種選択の違いが通信によるものかはリプレイだけでは判定できない。
- 1日目の混雑は完全一致。2〜5日目は267交通セルのうち順に40/51/70/86セルで混雑値が異なった。同じ試合内では全チームが同じ混雑入力を受ける。
- 最終日の混雑status 0/1/2のセル数はD0 90/138/39、C012 97/116/54。重い混雑セルは増えた一方、非混雑セルも増えており、全経路に一律に不利と結論しない。

### 最終日の補給待ちは観測できるが、−3玉の直接原因とは確定しない

C012の収集車0は4日目をpos988/fuel36で終えた。最終日はstep 5にpos991へ着き、fuel31で停留し、補給車が到着したstep 27に163を補給した。位置が変わらない区間は22ステップあり、次の移動はstep 29。このため終端配置と翌日の補給合流を改善する余地はある。

ただしD0には同じpos988から出発し、同じ6店舗を同じ順序で回ってpos25へ終わる収集車2がある。D0は開始fuel194で、同じ6店舗をstep 1/5/48/55/61/67に取得、C012はstep 1/5/71/80/84/90に取得した。**両者とも6玉で、D0の早着分はこの記録では追加得点になっていない。** この補給待ちを取り除けば直ちに3玉回復すると主張する根拠はない。

最終日の残り5収集車の玉数が合計68→65で、こちらが−3玉の実際の差である。C012収集車は最終日を通して燃料0にならず、最小燃料は車ごと31/84/38/91/33/43だった。燃料切れによる停止と説明することもできない。

## 次の評価へ残す判断

1. 現在の同条件D0/C012反復を完了し、16盤面の順位改善が再現するか、32盤面で同じ程度の逆行が続くかを見る。1回の順位差と小さな+4玉だけで採用せず、保存済みの比較計画に従う。
2. seed 11は車種・前日終端・共有混雑がすべて変わる。日中通信の内部効果は別の通信診断記録と併せて検討し、リプレイだけで通信の有効・無効を決めない。
3. 今後の設計仮説は「余った燃料」だけでなく、終端位置・翌日の店舗配分・補給合流までの所要時間を評価すること。ただし今回の22ステップ待ちに対応する車は同じ6玉を得ており、この1例から改変や追加テストを開始しない。
4. 大盤の減点箇所は追加玉の配分である。再現性があれば、共有候補の評価でも全種類を維持した後の店舗追加回収と翌日状態を重視できるか検討する。現時点では仮説であり、本分析から実装変更は行っていない。
