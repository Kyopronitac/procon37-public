## 基準実装：ビームサーチ・ALNSと厳密先読み

[ソース](solver01.rs) / [詳細アルゴリズム](solver01/algorithm.md) / [設定](solver01/settings.md) / [当時の検証](solver01/validation.md)

提供されたC++版「戦略9」のRust移植を基に、補給と混雑を含む候補再評価を加えた版。
巡回車ごとの訪問目標列を探索し、補給車の担当と実際の行動列を組み立てる。

1. 店舗までの最短経路を作る。同じ所要時間なら省燃料を選び、経路をキャッシュする。
2. 貪欲法で初期解を作り、位置・燃料・在庫・系列集合を持つビームサーチで改善する。
3. ALNSでランダム・迂回・近接・車両単位・連続区間の除去と、貪欲・regret-2・乱択の再挿入を組み合わせる。独立セッションで再スタートする。
4. 多様な候補を最大12件保存し、補給を含む行動列を厳密に再生して最大2日先まで比較する。通常の反復内では軽量な貪欲先読みを使う。
5. 選んだ候補の翌日計画を保存し、観測状態が一致する場合に再利用する。出力前に全車の行動を時刻順で検査する。

車種選択は貪欲な全日試行で候補を絞り、上位16案を日次ソルバによる全日試行で比較する。
主な対応箇所は `solver::assignment`、`beam`、`alns`、`neighborhood`、`supply`、`replay`。
`cover`・`coverbeam`・`horizon`・`population`・`repair` などの実験用モジュールとテストも原コミットのまま同じファイルに収める。
探索seedの省略時は現在時刻を使い、`PROCON37_` 系の環境変数で設定する。

## 再構築1：訪問列と補給合流の同時最適化

[ソース](solver02.rs) / [詳細アルゴリズム](solver02/algorithm.md) / [設定](solver02/settings.md) / [当時の検証](solver02/validation.md)

巡回車と補給車の両方に同じIDの合流を置き、訪問先・順序・合流地点・担当補給車を焼きなまし法で同時に探索する再構築版。
基準実装のALNS中心の構成から、短い訪問列を繰り返し評価する構成へ変わった。

店舗と車両現在地を端点とし、時間 `t`・燃料 `f` に対して `1024t + f`、`16t + 8f`、`4t + 8f` の3種類のDijkstra経路を前計算する。
合流の依存関係を解いて先着車を待たせ、循環する候補を棄却する。
探索途中では時間超過と燃料不足に罰則を与え、実行可能な最良候補を別に保存する。

新規系列・当日の系列・玉数に加え、翌日へ残す燃料と補給車への距離を評価する。
20,000反復ごとに温度と探索位置を戻す。
車種選択では補給車1台以上・全台数の半分以下の組合せを全日試行し、有望な配置を再探索する。
最大2日先読みも実装しているが、この版では `SOLVER_LOOKAHEAD=1` で有効にする実験機能であり、既定は単日探索である。

主な対応箇所は `solver` 内の評価・探索・車種選択、`solver::paths` の経路前計算、`solver::tests` の照合テスト。
通信は `main` が担当し、標準設定では要求時間から1.5秒を残して探索する。

## 再構築2：複数の当日候補と最大2日先の比較

[ソース](solver03.rs) / [詳細アルゴリズム](solver03/algorithm.md) / [設定](solver03/settings.md) / [当時の検証](solver03/validation.md)

訪問・合流の焼きなましに、巡回車間の訪問交換や経路後半の交換を加え、先読みを既定で使う版。
3種類の経路の辺コストは `1024t + f`、`16t + 12f`、`1024f + t`。
合流を時刻0で処理せず最低1ステップ待つことや、問題ごとの系列ID圧縮を含む。

通常は当日の6候補を作り、引継ぎ計画があれば加える。
各候補を `Game::play_day` で実行してから最大2日先を探索し、実際の燃料・位置・交通量を引き継いだ得点で比較する。
上位3候補には追加の先読み時間を割り当てる。この追加段階では当日の訪問列を固定する。
最良候補の翌日計画は、日番号・車両状態・交通量が一致したときに再利用する。
最終日は先読みをせず当日の改善に時間を使う。

焼きなましの温度は経過時間に沿って約8回上下する。
車種選択は補給車1〜2台かつ全台数の半分以下の組合せを全日試行し、初回上位3配置を再試行する。1台の場合は巡回車を選ぶ。
主な実装は `solver`、経路前計算は `solver::paths` にまとまる。
要求時間の2.5%（15〜1000 ms）を予約し、`SOLVER_BUDGET_MS`・`SOLVER_HORIZON` で短縮・先読み無効化を指定できる。

## 再構築3：4経路モード・高速集計・仕上げ探索

[ソース](solver04.rs) / [詳細アルゴリズム](solver04/algorithm.md) / [設定](solver04/settings.md) / [当時の検証](solver04/validation.md)

時間・燃料の重みを `(100, 1)`、`(100, 35)`、`(100, 100)`、`(1, 100)` の4通りに増やした再構築版。
通過店舗を32ビットで持ち、訪問台数ごとの集合と在庫集合から玉数を数える。
系列集合の参照表、候補配列の再利用、対応CPUでのPOPCNTを使い、反復あたりの評価を軽くする。

単日予算の88%を焼きなましに使い、残りで挿入・削除・移動・反転・経路変更・合流場所変更などの近傍を列挙する。
残燃料と補給車までの距離の重みを変えた複数の計画を、実際の最大3日分の先読みで比較する。
保存済みの訪問列を維持した候補も比較に残し、未保存の日だけ追加探索する。
日別先読みでは当日に将来の各日の2倍の探索時間を割り当てる。

車種選択は補給車0〜2台を含む配置を全日程で比較する。
同じ補給車数の配置間では、巡回車・補給車の役割を保って訪問列を移植する。
対応箇所は `solver::paths`（前計算）、`search`（評価・焼きなまし・仕上げ）、`planner`（車種選択・先読み）。
探索時間を変更する独自環境変数はなく、要求時間の1%（10〜600 ms）を予約する。

## 再構築4：固定長訪問列・途中合流地点・計画保持

[ソース](solver05.rs) / [詳細アルゴリズム](solver05/algorithm.md) / [設定](solver05/settings.md) / [当時の検証](solver05/validation.md)

記録作成時点の既定ソルバに対応する版。各車の訪問列を最大48件の固定長配列にし、経路の複製・変更時の割当を減らす。
4種類の経路重みは `(100, 1)`、`(100, 30)`、`(100, 100)`、`(1, 100)`。
店舗と開始位置に加え、店舗間の最短経路でよく通るセルを最大16地点、合流候補として追加する。
店舗まで迂回しない途中合流を表現できる。

単日探索は90%を焼きなまし、残りを近傍列挙に使う。
通常の訪問・合流変更のほか、巡回車の訪問を残した合流解除、未訪問店舗を優先する挿入を使う。
重複訪問は行動列を変えずに圧縮する。
翌日に必要な燃料量と補給車との距離を評価し、燃料・翌日目的地・車両ごとの訪問報酬を変えて候補を作る。

日別回答では最大3日分を比較する。保存済み部分は行動列をそのまま実行し、不足日だけを追加探索した候補も残す。
車種選択は補給車0〜2台を全日試行し、各台数の最良を含む最大5候補を維持する。
種類数・日別種類数・玉数の実得点で比較し、先読みの先に日程が残るときだけ残燃料を少し加点する。

対応箇所は `solver::network`、`routing`、`strategy`、`random`。
要求時間の1%（15〜700 ms）を検証と出力用に予約する。
