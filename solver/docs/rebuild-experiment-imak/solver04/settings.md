# 実行設定

再構築3（`6961e7b`）の資料。記録ソース: [solver04.rs](../solver04.rs)。
[比較対象のアルゴリズム](../algorithms.md#solver04)。

本文中の旧ファイル名は、単一ファイル内の同名モジュールを示す。当時のアルゴリズム・設定・検証記録を保存し、参照先と実行コマンドを現在の配置へ更新した。
検証の数値・実行ファイルのハッシュ・「現在」などの記述は原コミット時点の記録であり、今回の単一ファイル化後に再計測した性能値ではない。

実行例を使う前に `cargo build --release --manifest-path solver/docs/rebuild-experiment-imak/Cargo.toml --target-dir target --bin solver-04` で対象版をビルドする。

- 探索 seed は実行ファイルの第1引数。既定は0。
- 問題を識別する seed や、保存されたリプレイは探索に使わない。
- 制限時間は各要求の `timeLimitMs` を使用する。
- 通信と最終検証の余裕は `clamp(timeLimitMs / 100, 10, 600)` ms。
- 日別の既定60秒では約59.4秒、車種選択の90秒では約89.4秒、120秒では約119.4秒を使う。
- 時間制限を短縮する環境変数や固定の反復数制限はない。
- ソルバ内部は1スレッド。テスタ側の `--jobs` でケースを並列実行する。

探索は実時間で打ち切るため、同じ探索seedでもCPU負荷や実行環境によって得点が変わる場合がある。

短縮テストはテスタの `--time-limit-ms` を指定し、一時ディレクトリへ保存する。
正式比較は既定の制限時間で seed 0〜59 を実行し、`.tester/runs/` に保存する。
