# ソルバ再構築実験の結果まとめ

このブランチでは、既存ソルバを基準として4回の再構築を行い、その都度、本番条件の60問題で結果を比較した。
記録された合計は、基準実装の **種類数1055・日別種類数7061・玉数11765** から、再構築4の **1055・7120・16150** となった。
種類数を維持し、日別種類数は59、玉数は4385増えている。

ここでは各再構築で採用した設計と測定結果を対応付け、改善の内容と比較上の限界を整理する。
実験に使ったソルバの単一ファイル記録、アルゴリズムの詳細、実行設定、検証資料もこのディレクトリにまとめている。
開発用の `main.rs` と `solver/` 内の分割ソースは別途維持する。

## 実験の対象と比較方法

基準は `cc3277f` のビームサーチ・ALNSを用いる実装。以後の4コミットで探索実装を再構築し、直前の実装と比較した。
各再構築の資料では、旧探索コードを復元・流用せずに実装したことを記録している。
複数の設計要素をまとめて変更しているため、個々の手法だけの効果を測る実験ではない。

| 対象 | コミット | 主な設計 | ソース・詳細資料 |
| --- | --- | --- | --- |
| 基準実装 | `cc3277f` | 貪欲初期解、ビームサーチ、ALNS、候補の厳密先読み | [solver01.rs](solver01.rs) / [設計](solver01/algorithm.md) |
| 再構築1 | `cbeaafd` | 訪問と補給合流を同時に変える焼きなまし | [solver02.rs](solver02.rs) / [設計](solver02/algorithm.md) |
| 再構築2 | `c42d3ec` | 複数の当日候補を生成し、最大2日先で比較 | [solver03.rs](solver03.rs) / [設計](solver03/algorithm.md) |
| 再構築3 | `6961e7b` | 4経路モード、高速集計、仕上げ探索、最大3日計画 | [solver04.rs](solver04.rs) / [設計](solver04/algorithm.md) |
| 再構築4 | `6fd85e7` | 固定長訪問列、途中合流地点、保存計画の保持 | [solver05.rs](solver05.rs) / [設計](solver05/algorithm.md) |

ファイル番号01〜05は基準と4回の実験を識別するための番号である。
当時の開発記録に登場する `v1`・`v17` などの試作番号とは区別する。
未コミットの試作や実験用Pythonコードは収録対象に含めていない。

主な測定条件は以下のとおり。

- 生成器 `hex-udon-v19`、問題seed 0〜59、形式自動選択、探索seed 0。
- テスタの既定制限時間：車種選択60／90／120秒、日別回答60秒。
- 表に掲載する実行は24ケース並列、ソルバ内部は単一スレッド。
- 比較は同一問題かつ共通ACのケースで行い、種類数 → 日別種類数 → 玉数の順で勝敗を判定。
- 基準実装の探索予算は既定55秒。再構築後は要求時間から検証・出力用の余裕を引いて探索するため、実際の探索時間は同じではない。

以下は各実験時の保存済み結果であり、この資料作成時に全実装を一斉に再測定したものではない。
全実行が60件ACで、種類数の合計1055を維持した。

## 各再構築で得られた結果

### 再構築1：訪問と補給を一緒に探索する構成

ビームサーチ・ALNS中心の構成から、訪問列と合流IDを使った焼きなましへ再実装した。
合計の日別種類数と玉数は改善したが、1回戦の日別種類数は10減少している。
先読みを加える短縮実験では玉数を落とす傾向があり、この実験の採用設定では先読みを無効にした。
詳細は[検証記録](solver02/validation.md)を参照。

### 再構築2：当日の候補を先読みで選ぶ構成

巡回車間の交換などの近傍と、複数の当日候補を最大2日先まで比較する処理を採用した。
24並列の再構築1に対して59件で勝ち、日別種類数・玉数の合計も改善した。
当日の評価だけでなく、位置・燃料・交通量を引き継いだ試行結果で候補を選ぶ構成となった。
詳細は[検証記録](solver03/validation.md)を参照。

### 再構築3：探索速度と最良解の仕上げ

4種類の経路、高速な集合演算、焼きなまし後の近傍列挙、計画の再利用を組み合わせた。
採用結果の改善は日別種類数+1、玉数+52と小さく、21件では直前の実装に敗れた。
開発中には日別種類数が増えても玉数が減る候補があり、探索速度の改善だけでは最終得点の改善を保証しないことが記録されている。
詳細は[検証記録](solver04/validation.md)を参照。

### 再構築4：合流候補と保存計画の扱い

固定長の経路表現、保存計画の再生、燃料に応じた終点評価、店舗間の通過セルでの合流を採用した。
直前の実装に対して日別種類数+12、玉数+237となった。
開発中の短縮測定では、ビルドキャッシュによって別ラベルでも同一バイナリが使われた例を検出し、ハッシュで確認して再測定している。
詳細は[検証記録](solver05/validation.md)を参照。

## 結果の解釈

今回の記録では、4回とも直前の比較対象に対して日別種類数と玉数の合計が増えた。
ただし全ケースで改善したわけではなく、同じアルゴリズムでも実時間の打切りや計算機負荷によって結果は変わる。
複数回の独立測定による平均・分散の比較や、設計要素を1つずつ切り替える比較は、この本番結果表では行っていない。
したがって、再構築すること自体の効果や、特定の変更だけによる改善量をこの結果から切り分けることはできない。
