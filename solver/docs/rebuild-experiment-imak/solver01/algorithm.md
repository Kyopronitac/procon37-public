提供されたC++版「戦略9」を基に、実際の混雑・給油を反映する候補再評価を追加している。
日次計画は、巡回車ごとの「訪問目標スポットの列」で表し、最短経路を歩く行動列へ変換する。
最短経路が複数ある場合は、同じ所要時間で消費燃料の少ない経路を選ぶ。
経路の重みを実験設定で変えた場合も、主評価値が同じ経路の間で燃料を比較する。
同じ道路状態・出発点・経路の重みで組み立てた店舗までの経路は保存し、日次シミュレーション・貪欲先読み・ビーム展開から参照する。
保存先を店舗に限定して追加メモリを抑え、道路状態や経路の重みが変わった場合は別の経路として扱う。

## 車種選択

1. 全車巡回、補給車1台、必要に応じて補給車2〜3台の割り当てを列挙する。
2. 全日を軽量な貪欲法で進め、上位16案へ絞る。
3. 残り時間を候補間で分け、日次ソルバで全日を予行演習する。
4. **通算種類数 → 日別種類数 → 玉数 → 巡回車数**の順に比較して選ぶ。

予行演習では位置・燃料・前日と前々日の道路滞在量を持ち越す。
実際に出力する計画を時刻順に再生し、近似評価による得点で割り当てを決めない。

## 日次探索

```text
当日の道路状態で最短経路を準備
    ↓
補給車の担当候補を比較
    ↓
貪欲初期解 → ビームサーチで改善
    ↓
ALNSを独立セッションで反復
    ↓
候補プールを最大2日先まで実際に再生して再評価
    ↓
補給車の行動列を構築 → 全車を厳密に再生 → 回答
```

### ビームサーチ

| 項目 | 既定動作 |
| --- | --- |
| 状態 | 巡回車の位置・燃料・経過時間、訪問済みスポット、残在庫、獲得系列 |
| 遷移 | 経過時間が最小の巡回車の次の訪問目標を選ぶ |
| 経路 | 出発セルの地形・道路状態に基づくDijkstra最短経路 |
| 重複除去 | Zobrist hashで同一状態をまとめる |
| 幅 | 128から倍増。上限4,096。世代ごとの子ノードは65,536まで |
| 予算 | 長時間探索では5秒。短時間探索では日予算の1/10、最低200 ms |
| 採用 | 貪欲初期解を日次評価で上回った場合に置換 |

当日中に目標へ届かない場合も、途中まで進む計画として保持する。

### ALNSと再スタート

| 近傍 | 割合・内容 |
| --- | --- |
| 大きな除去・再挿入 | 60%。現在の解を広く組み替える |
| 小近傍 | 15%。移動・交換・区間反転・挿入・削除 |
| 適応的な除去・再挿入 | 25%。改善への貢献に応じて操作の選択重みを更新 |

除去はランダム・迂回が大きい点・近接した点・車両単位・連続区間の5種類。
再挿入は貪欲・regret-2・乱択の3種類。実行不能なツアー末尾の系列を「獲得済み」と誤認しないよう、日内に届く範囲から挿入価値を見積もる。

長時間探索では5秒の独立セッションを繰り返す。最終日は全体最良解から探索を続け、玉数の改善も採用する。
同じ候補の再評価を避け、当日新規種類数が劣る候補では将来日の評価を省く。

## 評価の優先順位

| 順位 | 比較対象 |
| ---: | --- |
| 1 | 当日に初めて獲得する通算系列数 |
| 2 | 将来日の先読みで増える通算系列数 |
| 3 | 当日の獲得系列数 |
| 4 | 将来日の獲得系列数の合計 |
| 5 | 当日の玉数 |

先読みは貪欲法による近似。20秒以上の探索では既定2日、短い探索では1日。
当日の道路状態を先読み中も使い、日次探索の反復ごとに将来の渋滞を厳密再計算することはしない。

55秒探索では末尾15秒を候補プールの再評価に割り当てる。
当日の新規種類数・獲得系列数が同じ候補を最大12案保存する。半分は近似先読みの評価、残りは経路ハッシュによる抽出で保持し、同じ終点でも途中の経路が違う候補を残す。

候補ごとに補給車の行動を含めて厳密再生し、位置・燃料・過去2日の道路滞在量を引き継いで、最大2日先まで実際の計画を探索する。
再評価では当日の新規種類数・獲得系列数を優先し、その後、先読み後の通算種類数、区間の日別種類数合計、玉数合計を比較する。
先読みの1候補・1日あたりの予算は残り時間から均等に割り当て、最大1.5秒とする。先読み子探索も親の回答期限を共有する。
途中までしか再生できなかった候補は、全区間を評価できた候補と混ぜて比較しない。

採用した候補の翌日計画は、実際の翌日の位置・燃料・道路状態が一致した場合に初期解として使う。
候補が不足する日はALNSを日予算の終わりまで続ける。
`EXACT_POOL=0` で従来の乱択貪欲法による再評価へ切り替えられる。

## 補給と回答検査

| 状況 | 動作 |
| --- | --- |
| 同じセルから出発 | 巡回車の行動を補給車が同時に実行する |
| 離れたセルから出発 | 巡回車が燃料不足になる位置へ合流し、到着まで待って給油する |
| 残り行程を満タン1回で走れる | 補給車を離脱させ、別の巡回車の給油へ向かわせる |
| 日末 | 到達可能で燃料の少ない巡回車の終端へ向かう |

探索中の近似評価とは別に、出力直前に全車の行動を時刻順で再生する。
移動完了時の燃料消費、車両番号順の在庫獲得、給油、その後の次行動予約を検査する。
予約時に燃料が足りなくても、移動完了前に補給を受ければ移動できる。燃料不足の判定は移動完了時に行い、そのステップの給油より先に消費する。
不正な計画を検出した場合は全車待機へ戻し、警告を標準エラーへ出す。

テスタから前日の回答が不採用と通知された場合は、通算の獲得系列を回答前へ戻す。
翌日の位置・燃料・車種は、テスタから渡された実際の状態を使う。
