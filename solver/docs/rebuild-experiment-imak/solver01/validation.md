## 移植時の検証方針

以下のC++版との比較と60ケースの成績は、生成器v10を使った移植時の記録である。

提供されたC++版「戦略9」のアルゴリズムをRustへ移植する。
同点候補の並べ替えにはRust標準ライブラリを使い、C++固有の候補順序や行動列の完全一致は要求しない。
**合法性・得点・実行時間**を確認し、移植元へ結果を合わせるための微調整は行わない。

| 対象 | 条件 |
| --- | --- |
| 移植元 | 提供されたC++ソルバ。GCC 13.3、`-O3 -std=c++17` |
| 移植元のSHA-256 | `c439fee4ce3f16d5615c3dad02c3f11ee8e48df27a7fbd953bffe8035be57b47` |
| Rust版 | このリポジトリの `main.rs` と `solver/` |
| 問題 | 生成器hex-udon-v10、seed 0〜59。公式サンプル3件を含む |
| 探索seed | 0 |

## 固定反復での比較

車種候補の予行演習を各日50反復、日次探索を500反復とし、時間に依存するビームサーチは無効化した。4ケース並列で実行。

| 実装 | AC | 通算種類数の合計 | 日別種類数の合計 | 玉数の合計 |
| --- | ---: | ---: | ---: | ---: |
| C++版 | 60/60 | 1055 | 6898 | 10206 |
| Rust版 | 60/60 | 1055 | 6892 | 10096 |

同点候補の順序が異なるため、同じ反復数でも探索経路と得点は変わる。
この比較は短い反復数での動作確認であり、既定55秒の性能差を表すものではない。

```sh
PROCON37_SEED=0 PROCON37_BEAM=0 \
PROCON37_ASSIGN_PLAN_ITERS=50 PROCON37_ITERS=500 \
  cargo run --release -p tester -- run 60 --jobs 4
```
