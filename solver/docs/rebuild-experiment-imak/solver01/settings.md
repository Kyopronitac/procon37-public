# ソルバの設定

基準実装（`cc3277f`）の資料。記録ソース: [solver01.rs](../solver01.rs)。
[比較対象のアルゴリズム](../algorithms.md#solver01)。

本文中の旧ファイル名は、単一ファイル内の同名モジュールを示す。当時のアルゴリズム・設定・検証記録を保存し、参照先と実行コマンドを現在の配置へ更新した。
検証の数値・実行ファイルのハッシュ・「現在」などの記述は原コミット時点の記録であり、今回の単一ファイル化後に再計測した性能値ではない。

実行例を使う前に `cargo build --release --manifest-path solver/docs/rebuild-experiment-imak/Cargo.toml --target-dir target --bin solver-01` で対象版をビルドする。

- ソルバの入口 → [比較対象のアルゴリズム](../algorithms.md#solver01)
- アルゴリズム → [algorithm.md](algorithm.md)

設定名にはすべて `PROCON37_` を付ける。真偽値は `0` が無効、`1` が有効。
特に指定しなければ、60ケースで確認した2日先読み・同距離の省燃料経路・店舗経路の再利用と、メモリ消費を抑えたビーム上限を使用する。

## 通常の実行

| 設定 | 既定値 | 内容 |
| --- | ---: | --- |
| `SEED` | 現在時刻 | 探索の乱数seed。第1引数があればそちらを優先 |
| `ASSIGN_MS` | 55000 | 車種選択の時間予算（ms） |
| `TIME_MS` | 55000 | 日次探索の時間予算（ms） |
| `DEPTH` | 自動 | 先読み日数。20秒以上なら2、それ以外は1 |
| `DEBUG` | 0 | 1で探索統計、2でビーム幅ごとの情報を標準エラーへ出す |

テスタの `timeLimitMs` にも従い、回答処理用に500 msの余裕を設ける。
前計算も含めて要求の締切を確認する。短い時間制限を使う場合は、ソルバ側の探索時間も明示すると比較しやすい。

## 再現性のある比較

```sh
procon37_test_dir="$(mktemp -d /tmp/procon37-record01.XXXXXX)"
PROCON37_SEED=0 PROCON37_BEAM=0 \
PROCON37_ASSIGN_PLAN_ITERS=50 PROCON37_ITERS=500 \
  cargo run --release -p tester -- run 60 --jobs 4 --label '第1版・記録再生・固定反復60件' --output-dir "$procon37_test_dir" --no-build --solver target/release/solver-01
```

| 設定 | 既定値 | 内容 |
| --- | ---: | --- |
| `ITERS` | 0 | 日次探索の反復上限。0は時間制 |
| `ASSIGN_PLAN_ITERS` | 0 | 車種候補の予行演習を反復固定する。0は時間制 |
| `BEAM` | 1 | ビームサーチの有効・無効 |

厳密な再現には、乱数seedと反復数を固定し、時間で打ち切るビームを無効にする。
車種候補の予行演習は、反復固定時には自動でビームを無効にする。
反復固定は移植の検証用であり、既定55秒の性能測定とは分ける。時間制では同じseedでも実行環境や負荷により結果が変わる。

## 探索の調整

| 設定 | 既定値 | 内容 |
| --- | ---: | --- |
| `ASSIGN_K` / `ASSIGN_PLAN` | 16 / 1 | 予行演習する車種候補数・有効化 |
| `ASSIGN_R` | 1 | 0以下で予行演習を無効化する互換設定 |
| `NUM_SUPPLY` | -1 | 補給車台数を固定。負値なら自動。C++のコンパイル時設定に相当 |
| `BEAM_MS` | 自動 | ビームの時間予算。負値なら自動 |
| `BEAM_W` / `BEAM_K` | 128 / 64 | 初期幅・展開あたりの候補数 |
| `BEAM_WCAP` / `BEAM_CCAP` | 4096 / 65536 | 幅・世代ごとの子ノード数の上限 |
| `PATH_FUEL_TIE` | 1 | 同じ経路評価値なら消費燃料の少ない経路を優先する。通常設定では所要時間を維持する |
| `PATH_CACHE` | 1 | 同じ出発点から店舗までの経路を保存して再利用する。経路の選択は変えない |
| `BEAM_POT` | 1.0 | 最寄りの有価スポットまでの距離ペナルティ |
| `SESSION_MS` | 5000 | 独立セッションの長さ。明示すると短時間探索でも分割 |
| `RESTART_P` / `MUTATE_P` | 0.60 / 0.15 | 大きな組み替え・小近傍の割合。残りはALNS |
| `RESTART_MODE` | 1 | 1は既存解の組み替え、0は乱択貪欲で作り直す |
| `SESSION_MODE` | 1 | 追加セッションの初期解。0は乱択貪欲、1はビーム解の組み替え、2はビーム解 |
| `FINAL_CONTINUE` | 1 | 最終日は全体最良解から継続 |
| `MEMO` / `LAZY` | 1 / 1 | 重複候補の省略・劣る候補の先読み省略 |
| `RETRY` / `RETRY_MODE` | 8 / 0 | 重複候補の再提案回数・方式。0は小近傍、1は削除なし、2は除去・再挿入 |
| `POOL` / `POOL_CAP` | 1 / 12 | 候補プールの有効化・容量 |
| `EXACT_POOL` | 1 | 補給・燃料・道路滞在量を実際に再生して候補を先読みする。0は従来の乱択貪欲法 |
| `POOL_DIVERSE` | `EXACT_POOL`と同じ | 訪問順の異なる候補を保持する |
| `EXACT_POOL_DEPTH` | 2 | 候補再評価の先読み日数。残り日数で制限する |
| `EXACT_POOL_MS` | 自動 | 候補再評価へ予約する時間。日予算の1/3または15秒の小さい方（ms） |
| `EXACT_POOL_DAY_MS` | 1500 | 候補1件・先読み1日あたりの時間上限（ms） |
| `FUTURE_NK` / `FUTURE_BALLS` | 1 / 0 | 将来日の新規系列・玉数を評価へ加える |
| `COVERAGE` / `EXACT_CLAIMED` | 1 / 1 | 日内に届く範囲から挿入価値を計算・厳密再生で獲得系列を更新 |

## 実験用モード

元のC++版の切り替えを残している。既定以外の設定が常に性能を上げるとは限らない。

| 設定 | 既定値 | 内容 |
| --- | ---: | --- |
| `SUPPLY` | 2 | 0は合流後に同伴、1は給油後に解放、2は遅延離脱、3は帰還付き離脱 |
| `BEAM_STEP` | 0 | 0はスポット単位、1は1セル、2は両方、3は同期1セル、4はスポット→同期1セル、5は幅固定スポット |
| `OROPT` | 0 | 2〜3点の連続区間移動を小近傍へ追加 |
| `NEIGHBOR` | 0 | 1で除去・再挿入へ統一し、規模を連続的に変える |
| `INIT` | 0 | 1はビーム無効時に多スタート貪欲、2は最初のビーム解を採用 |
| `INS` | 0 | 1で到達不能な挿入や後続スポットの押し出しを減点 |
| `REACH` | 0 | 貪欲先読みを、翌日の到達可能系列集合による評価に置換 |
| `VERIFY_DEPTH` / `VERIFY_AGG` | 1 / 0 | 候補再評価の先読み日数・集計。集計1は日数分を合計 |
| `PHASEC` | 0 | 候補再評価後に探索を続ける時間（ms） |
| `ATB` | 0 | 系列数20未満の盤面で将来の玉数も重視 |
| `SA` / `SA_T0` / `SA_T1` | 0 / 4.0 / 0.3 | セッション内の焼きなまし・開始温度・終了温度 |
| `POP` | 0 | 複数個体の焼きなまし探索 |
| `POP_W` / `POP_ELITE` | 自動 / 自動 | 個体数・淘汰後に残す数 |
| `POP_CULL_ITERS` / `POP_CULL_MS` | 240 / 1200 | 淘汰間隔。反復数の実効下限は個体数×40 |
| `POP_BRANCH` | 2 | 分岐時に重ねる近傍操作数の基準 |
| `EXACT_POOL_TOTAL` / `POOL_DAILY_SLACK` | 0 / 1 | 複数日の合計で候補を比較し、当日の種類数が指定数少ない候補も保持する実験 |
| `EXACT_POOL_RACE` / `EXACT_POOL_FINALISTS` | 0 / 4 | 再評価予算の1/3で全候補を評価し、残りで上位候補を詳しく評価する。再評価には現在の最良解も残す |
| `ASSIGN_RACE` / `ASSIGN_FINALISTS` | 0 / 3 | 車種選択の予行演習予算を二分し、前半で全候補、後半で上位候補を評価する。反復固定時は無効 |
| `STACK_TARGETS` | 0 | 貪欲先読みの候補配列をスタックに置き、ヒープ確保を減らす。並べ替え順・乱数消費は維持する |
| `SUPPLY_ENUM` | 0 | 補給車が複数台で補給先の全組み合わせが64通り以下なら、全てを貪欲計画・先読みで評価する。大きい場合は従来の代表候補を使う |
| `EXACT_POOL_SEARCH_DEPTH` | 0 | 候補再評価の各日探索が考慮する先の日数。0〜2。再評価の対象日数 `EXACT_POOL_DEPTH` とは別の設定 |
| `EXACT_POOL_RESERVE` | 0 | 先読み後にも日数が残る場合、種類数・日別種類数が同点なら、移動可能な巡回車数・巡回車の最小燃料・燃料合計を玉数より先に比較する |
| `ROLLOUT_ESCORTS` | 0 | 貪欲先読みの同伴補給を当日の終了状態から決める。途中離脱・夜間の給油先・同じ巡回車に同伴する複数補給車を考慮する |

実験経路にあったC++の関数引数の未規定な評価順序は、Rustでは明示した乱数消費順に固定する。
