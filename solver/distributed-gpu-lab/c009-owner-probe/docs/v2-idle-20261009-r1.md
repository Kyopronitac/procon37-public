## 原因の推定と次回の最小変更

C009の`join_delegated_group`は`writeln!(file,"{tid}")`でcgroup v1の`tasks`へ書いている。可変formatは数字と改行を別writeにする可能性があり、TIDを書いた後の改行だけのwriteが`EINVAL`になる説明と整合する。現在のerrorにはopen/writeの文脈がなく、straceも実施していないので、どのsyscallで失敗したかは未確定。

次回の最小変更候補はTIDと改行を先に一つのbufferへformatし、一回のwriteで渡すことと、open/writeエラーに対象操作を添えること。cgroupは一回のwriteをコマンドとして扱うので、通常file向けの断片化したformat書込みを避ける。凍結C009を無言で差し替えず、修正候補のsource/binary SHAとCPU検証を新規記録する。親担当が次の区切りを認めるまで、修正・再ビルド・再試行を行わない。

GPU利用の有用性判断は保留。今回の設定エラーをGPU性能が悪い根拠として扱わない。

追記：一次資料でも、cgroup v1の`tasks`には1回の書込みで1つのTIDを渡す操作が説明されている。[Linux kernel cgroup v1 documentation](https://docs.kernel.org/admin-guide/cgroup-v1/cgroups.html)。Rustの`write_fmt`は内部で`write_all`を使い、単一の書込み呼出しを保証するAPIではない。[Rust std::io::Write documentation](https://doc.rust-lang.org/stable/std/io/trait.Write.html#method.write_fmt)。これらは修正方針の根拠であり、今回実際に失敗したsyscallの特定には代わらない。
