# 並列pool 第3世代P0

固定共通基準から構築する。制御1スレッドと探索14スレッドを使用する。各探索は独立した乱数・温度倍率・ビームの時間減点を持ち、グラフと評価キャッシュはスレッド内に保持する。2本ずつ7組に分け、終端の燃料不足に対する減点係数を4・8・12・15・20・30・45へ分散する。同じ係数の組内で当日の最良案を共有し、冷却周期の境界で採り込む。選択した計画の実行前状態・取得済み種類・前日の滞在数・訪問列を全探索へ同期する。

車種選択は探索番号を車両数で割った余りを補給担当とし、初日62%・残りを翌日の試算に使う。初日の回収評価＋翌日評価×0.75＋初日の燃料等の評価×0.05で比較し、日別計画と基準を揃える。通常計画は全サイズで当日67%・残りを翌日の試算に使う。候補選択は当日の回収評価＋翌日の共通係数15での評価×0.75＋当日の燃料等の評価×0.05。16店舗以下かつ試算に1500ms以上を使える場合は、通常の交通予測と、現在の混雑道路が少なくとも混雑のまま残る予測をそれぞれ探索し、低い方の翌日評価で比較する。翌日用の計画を選択案と一緒に引き継ぐ。要求時間3500ms未満と最終日は当日だけを探索し、共通係数15で比較する。

ビルドはこの候補のルートで `PATH=/home/jikky/.cargo/bin:$PATH cargo build --release -p solver -j 2`。起動引数は探索seed 0のみ。`PROCON37_G007_FUTURE_WEIGHT=0`、`PROCON37_G007_RESERVE_WEIGHT=15` をランチャーで固定する。P0は team0、192.168.0.11、CPU集合 `0-3,8-11,16-19,24-26`。

独立探索間では実装や評価キャッシュを共有せず、計画候補と採用状態を受け渡す。提出前には公開判定エンジンで各探索の最終案を検証する。相手5体はブラックボックスとして扱う。
