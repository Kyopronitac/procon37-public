# 探索と実行設定

## 並列探索

標準入力と標準出力を扱う制御スレッドに加え、14個の探索スレッドを使用します。各探索スレッドは単一スレッド基準の独立した状態と経路グラフを持ち、seedを206002＋7919×worker番号として探索します。探索中に別のスレッドやプロセスを生成しません。

車種選択では、worker番号を車両数で割った余りを補給役として担当します。要求時間に応じて初日から最大3日を試算し、初日評価＋翌日評価×0.65＋翌々日評価×0.35で補給役を選びます。採用する内部状態は初日の計画を作った直後へ戻します。

計画要求では採用済みの計画、共通エンジンの履歴、取得済み種類、補給役と初期解を全workerへ同期します。各workerの乱数状態は維持します。4096反復ごとに最良案を共有し、焼きなましの再開周期に、他workerの良い案を取り込みます。グラフ番号の違いは実座標を介して補給点を変換し、取り込んだ案を自分の評価器で評価し直します。探索途中の経路は各workerに保持し、提出前に既存の公開エンジンによる妥当性検証を通します。

店舗数16以下は基準と同じ玉数評価20を使い、それより大きい盤面では玉数評価を1個60へ変更しました。種類数評価と燃料不足の減点は基準の値を維持します。経路評価・差分ビーム・全車経路組み合わせの報酬と上界は同じ玉数係数を使用します。

制御側は通常の要求時間から80msを引いてworkerへ渡します。worker側は基準と同様の期限余裕を確保します。110ms以下の追いつき要求では元の要求時間を渡し、基準の同期と待機処理を使います。小盤面で要求時間5000ms以上なら、当日予算の20%を翌日種類数の比較へ配分します。この場合は翌日の種類数を含む比較値でworkerを選びます。
