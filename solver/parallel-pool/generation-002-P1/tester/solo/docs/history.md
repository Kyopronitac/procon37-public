# 履歴の比較・移動・保存形式

- テスタの入口 → [../README.md](../README.md)
- CUI → [usage.md](usage.md)
- GUI操作 → [gui.md](gui.md)

履歴は既定で `.tester/runs/<実行ID>/` に保存する。実行IDはCUIのサマリー・結果保存先に表示され、ディレクトリ名にもなっている。サーバー再起動後も再生できる。

## 比較の対象と勝敗

**同じseedでも、問題が同じとは限らない。** 比較では保存された問題本体と形式を照合し、選択した全履歴で「同一問題かつAC」のケースを使う。

| 表示 | 集計するケース |
| --- | --- |
| 単独履歴のスコア合計・形式別合計 | 完了済みの全ケース。WA・TLE・REの代替動作による得点も含む |
| 単独履歴の判定件数 | 完了済みの全ケース |
| 比較の勝敗・スコア合計・差分・共通ACの平均 | 選択した全履歴で同一問題かつAC。形式の絞り込みを反映 |
| 比較に表示する各履歴の判定件数 | 各履歴の全完了ケース。形式の絞り込みによらない |

単独履歴の合計は一覧の絞り込みによって変わらない。比較画面でも、スコア合計や形式別勝敗はケース表示条件には連動せず、形式の絞り込みに連動する。

勝敗は **種類数 → 日別種類数 → 玉数** の順で決める。回答時間は別表示。時間は環境・並列数の影響を受けるため、実行条件と併せて比較する。

比較・PRの報告は、**種類数・日別種類数・玉数の合計を以前と変更後で並べた表**と、**以前に対してA勝B同点C敗**を基本とする。勝敗は変更後から見た件数で、合計と同じ比較対象集合を使う。

| 比較から除外される状態 | 扱い |
| --- | --- |
| 問題が異なる | 問題相違として区別 |
| 未実行 | 未実行として区別 |
| 問題ファイルがない | 問題確認不可として区別 |
| 同一問題だがAC以外 | 非ACとして区別 |

比較は保存データの読み取りだけを行い、ソルバを再実行しない。実行途中の履歴は取得時点の状態を使う。

## GUIで比較する

1. 「履歴を比較」を押す。
2. 表示されたチェックボックスで2〜4件を選び、「比較する」を押す。
3. 基準の履歴と形式を選び、勝敗・スコア合計・差分を見る。
4. 詳しく調べるケースの「再生」を押す。

| 表示 | 読み方 |
| --- | --- |
| 勝・同点・敗 | 基準に対する件数と内訳のバー |
| 形式別の勝敗 | 1回戦・準決勝・決勝の内訳。基準側には共通AC件数を表示 |
| スコア合計 | 種類数・日別種類数・玉数。基準との差を併記 |
| 平均・形式別内訳・実行条件 | 平均、各履歴の全完了ケースの合計、並列数、制限時間 |
| ケースごとの表示値 | 種類数・日別種類数・玉数・回答時間から選択 |
| 比較対象なし | 「—」で表示 |

実行途中の結果を取り直す場合は「比較を更新」を押す。

## CUIで比較する

```sh
# 最初のIDを基準に比較
cargo run --release -p tester -- compare RUN_ID_A RUN_ID_B

# 基準を変更し、決勝だけを比較
cargo run --release -p tester -- compare RUN_ID_A RUN_ID_B --baseline RUN_ID_B --format final

# 3件の比較をJSONで保存
cargo run --release -p tester -- compare RUN_ID_A RUN_ID_B RUN_ID_C --json > comparison.json
```

| オプション | 指定 |
| --- | --- |
| 実行ID | 2〜4件。インポート済みの履歴も使用可能 |
| `--baseline ID` | 比較対象のID。省略時は最初のID |
| `--format` | `first` / `semifinal` / `final` / `all`。既定は `all` |
| `--output-dir DIR` | 別の履歴保存先を使う |
| `--json` | 集計結果を標準出力へJSONで出す |

通常表示では、スコア合計の括弧内が基準との差。対象なしは `-` を表示する。

レポートを出力できた場合の終了コードは0。敗北や非ACの記録を含んでも変わらない。不正なオプション・存在しないIDなどは非0。

### 比較JSON

| フィールド | 内容 |
| --- | --- |
| `schemaVersion` | 1 |
| `runs` | 実行情報・各履歴全体の判定件数 |
| `scopes` | 全体・形式別の対象件数、勝敗、スコア合計、差分 |
| `format: null` | 全体の集計 |
| 勝敗・差分の `null` | 基準側、または共通ACがない場合 |
| スコアの `null` | 共通ACがない場合 |

## 実行履歴を端末間で移す

### GUIの手順

1. 履歴を開いて「履歴をエクスポート」、または履歴カードの「ZIP出力」を押す。
2. `run-実行ID.procon37.zip` を別の端末へコピーする。
3. 移動先で「履歴をインポート」からZIPを選び、「取り込む」を押す。実行名は変更可能。
4. 取り込んだ履歴を再生・比較する。

取り込んだ履歴には「取込」と表示する。再生・GIF出力・比較・削除・再エクスポートが可能。

### CUIの手順

```sh
cargo run --release -p tester -- export RUN_ID --output laptop.procon37.zip
cargo run --release -p tester -- import laptop.procon37.zip --label 'ノートPC · 改善版'
```

`--output-dir DIR` で履歴保存先を変更できる。`export` の出力先省略時はカレントディレクトリの `run-実行ID.procon37.zip`。既存ZIPは上書きしない。`import` の `--label` 省略時は元の実行名を使う。

### 移動されるもの

| 項目 | 扱い |
| --- | --- |
| 日時・設定・判定・得点・問題・リプレイ・ログ | 保持 |
| ビルド・ソルバのコマンド・引数・作業ディレクトリ・環境変数 | 取り込み時にこの端末の既定値へ置き換える |
| ソルバのソース・実行ファイル | ZIPに含まない |
| 実行ID | 取り込みのたびに新規発行。既存履歴を上書きしない |
| ビルド・ソルバ実行 | 取り込み時には行わない |

取り込んだ履歴で「この設定で再実行」を使うと、実行コマンドにはこの端末の既定値を使う。以前のバージョンで取り込んだ履歴も同様。別のソルバを使う場合は、実行画面で自分のコマンドを指定する。

完了・中断・失敗（CEを含む）の履歴を移動できる。実行中は完了または中断を待つ。中断時は保存済みの完了ケースを含む。

### ZIPの形式と上限

| 項目 | 値 |
| --- | --- |
| 識別情報 | `archive.json` の `format: "procon37-run"` / `version: 1` |
| 圧縮後のサイズ | 256 MiBまで |
| 展開後のサイズ | 1 GiBまで |
| 単一ファイル | 64 MiBまで |
| 完了ケース数 | 10,000件まで |

取り込み時はパス・内容を検証し、保存された回答から試合を再計算する。行動計画・交通情報・各ステップの状態・得点・判定が記録と一致しないZIPは受け付けず、途中の履歴も残さない。ソルバ自体の再実行は不要。

「JSONファイルを開く」は単一の問題・リプレイの一時閲覧。実行履歴の移動にはZIPを使う。

## 履歴を削除する

1. 履歴の「削除」を押す。
2. 実行名・日時・件数を確認する。
3. 「削除する」を押す。

その実行の結果・問題・リプレイ・ログをまとめて削除する。**取り消せない。** 実行中は削除できない。

表示中の履歴を削除すると別の履歴へ移動し、比較対象からも除外する。ブラウザで削除済み履歴へ戻った場合も、残っている履歴を表示する。

## 保存結果

```text
.tester/runs/<実行ID>/
├── run.json             # 設定・状態・各seedの集計
├── build.stdout.log     # ビルドした場合
├── build.stderr.log
└── <seed>/
    ├── problem.json     # 公式形式の入力、startsAt=0
    ├── replay.json      # 問題・回答・採用計画・状態・得点
    └── stderr.log       # ソルバのログ
```

### 実行記録：run.json

| フィールド | 内容 |
| --- | --- |
| `schemaVersion` | 3 |
| 実行の `status` | 実行中・完了・中断などの状態 |
| 実行の `verdict` | 完了時のAC/WA/TLE/RE、またはビルド失敗時のCE |
| ケースの `status` | AC/WA/TLE/RE |
| `execution` | 利用可能CPU数・実際の同時実行条件 |
| `error` | ディスク書き込み失敗など、テスタ側の異常 |

旧版の判定は読み込み時に変換し、元のファイルは書き換えない。

### リプレイ：replay.json

| フィールド | 内容 |
| --- | --- |
| `schemaVersion` | 1 |
| `case.generatorVersion` / `case.seed` | 生成方式のバージョンとseed |
| `selectionAnswer` / `selectionFailure` | タイプ選択の回答と失敗 |
| 日別の `submittedAnswer` | ソルバが提出した回答 |
| 日別の `plan` | 実際に採用した計画。代替動作の場合もある |
| 日別の `failure` | 却下・時間切れなどの理由。受理時は `null` |
| `frames` | 各日0〜最終ステップの状態 |
| `uniqueBrands` / `dailyBrands` / `udon` | 試合全体の種類数／日別種類数の合計／獲得玉数 |
| `answerTimeMs` | 受理した日別回答時間の合計。タイプ選択を含まない |

得点の優先順は種類数・日別種類数・玉数の降順。回答時間は昇順で評価するが、履歴比較の勝敗には含めない。実時間を測るため、同じseedでも時間は変動する。

### ログと異常

標準エラー・各ビルドログは16 MiBまで保存し、それ以降も読み捨てを続ける。GUIにはログの末尾を表示する。

ソルバの起動失敗はRE。ディスク書き込みなどテスタ側の失敗ではバッチを中断し、`error` に原因を残す。回答の判定とは区別する。
