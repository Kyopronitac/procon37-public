# 第1世代 P0 候補

共通基準 `ca0218f665388632f0b365414c6ef80acb6ec7626193190c9c5ce483521c8d7a` から独立に構築した並列ソルバです。旧P0・他の並列候補・保護された保存版の実装は参照していません。

## 探索

制御1スレッドと常駐探索14スレッドを使います。当日の不変な経路グラフは制御側で一度だけ構築し、14探索で共有します。各探索のメモ、補給時刻表、燃料距離キャッシュ、乱数状態は独立です。探索候補の共有には車両の訪問列と補給地点の実座標を使います。冷却周期の境界で候補を交換し、各探索の評価で改善した全体案や他車の訪問列を取り込みます。補給時刻が異なる経路も常に再評価します。

探索島は終端燃料の不足への重みを0、2、5、10、15、25、40、ビームの時刻重みを0.5、2、4に分けます。10番以降の探索島は経路ビーム幅64、それ以外は32です。受信時間が短い場合は探索する島を減らしますが、作成するスレッド数は14を超えません。Tokioや他の並列ランタイムは起動しません。

車種選択は補給車の候補を探索島へ割り当て、十分な時間があれば初日から3日目まで試算します。日別計画では約64%の時間で当日案を探索し、候補から翌日を並列に試算します。各島は最良から評価120以内の案を探索中に保存し、終端位置の異なる最大5案も提出します。制御側が終端車両位置・燃料・予測交通で重複を除き、当日品質と終端距離を使って14案に絞ります。7秒の短縮要求でもこの先読みを使います。公開エンジンが計算した当日の種類、当日と翌日の合計種類、当日の種類、当日玉数＋翌日玉数×0.35を順に比較します。終端燃料は軽い同点評価にだけ用います。最終日は当日の得点で比較します。

## 履歴と通信

JSON Lines v1、起動引数は探索seed一つ（既定0）です。制御側が実際に提出した計画だけを保存します。次の要求の `previousAccepted` がfalseなら公開エンジンの待機計画を適用し、観測車両・交通・日付と同期します。全探索へ同じゲーム履歴と採用した計画の初期解を渡します。110ms以下の追いつき要求は探索を開始せず同期後に待機を返します。

各探索の提出候補は公開 `Game::play_day` で検証し、制御側で最終採用案も再検証します。標準出力は要求IDを保った回答JSONだけで、探索・選択のログは標準エラーに出力します。
