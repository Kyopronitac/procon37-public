# 第8世代ソルバの探索方法

本実装は第7世代を継続改善した単一スレッドのv117を、第8世代として登録したものです。公開通信仕様と共通判定エンジンを用い、対戦相手や保護された保存版の内部実装を改善へ流用していません。従来のsolver-pool方式による独立した新規開発ではありません。平均1.00位という目標は未達のまま、ユーザー指示により開発と評価を終了しています。

## 計画の表現

PR #22のレビュー修正では、要求の観測車種から補給役を同期し、役割が変われば以前の計画・経路グラフのキャッシュを破棄します。補給車がちょうど1台の場合は通常の探索を使います。それ以外の車種構成では、巡回車ごとに観測燃料と当日の残り時間で到達可能な店舗を選ぶ保守的な経路を作り、補給を仮定しません。公開エンジンで提出可能な計画であることを確認します。要求時間が110ms以下の追いつき要求では、以前の計画の採否と観測状態を同期した後、重い経路構築・探索をせず待機計画を返します。修正版の検証は[レビュー対応記録](pr-022-review.md)に分けています。

補給車を1台選び、当日の計画を探索します。開発比較用の第4引数を正に指定し、翌日があり回答時間が5秒以上なら、当日の有力案から翌日の計画も作って最終案を選びます。第4引数が0の既定動作では、店舗16以下・回答時間20秒以上・翌日がある場合に、後述の翌日の種類数を確認する比較を使います。それ以外は当日の探索へ時間を使います。開発比較用の環境変数で翌日重みを正に指定した場合は、別方式として翌日の計画も同時に変更する探索を使います。補給車には4箇所の立ち寄り先と出発時刻を与えます。候補位置には店舗・車両位置に加え、地図を5×5の領域へ分けて選んだ通行可能セルを用い、店舗間での待ち合わせも探索します。店舗数16以下かつ地図全体が256セル以下の場合は、全ての通行可能セルを補給地点候補とします。巡回経路上で提案した待ち合わせ位置を近くの格子点へ置き換えず、その位置を直接選択できます。店舗数が16を超える盤面では、店舗と車両の開始位置の隣接する通行可能セルも補給地点候補に加えます。巡回車には店舗と補給地点の訪問順を与えます。補給地点では、到着を待つか、補給車の出発まで待つかを選択できます。

当日は受信した交通状態を使用します。翌日の予測では、当日計画を公開エンジンのコピーで実行し、自チームの当日と前日の道路滞在数を使います。他チームの位置が観測できる場合は、各車両の現在位置を根とする最短経路木を作り、到達可能な店舗への需要を距離で重み付けして木へ加算します。各車両の推定滞在数を一日の移動時間へ正規化し、前日分と当日分を保持します。道路ごとの予測値は自チームの2日分の滞在数×0.5、他チームの経路木による推定×0.05、観測した交通区分から得る事前値×0.25の和です。事前値には、空いている道路で混雑閾値の0.25倍、混雑道路で混雑・渋滞閾値の平均、渋滞道路で渋滞閾値の1.3倍を使います。他チームの位置がない車種選択中の試算などでは、自チームの2日分×0.5を使い、現在の混雑・渋滞を少なくとも混雑として予測します。

地点間には時間優先、時間と燃料の両立、燃料優先、途中店舗の経由を優先する3段階の、合計6種類の経路を用意します。巡回車・補給車の両方で区間ごとの経路を選択します。店舗経由の経路は辺コストから店舗通過分を差し引き、辺コストを正に保って閉路を防ぎます。逆向きの最短路計算により、日の終了時に店舗間の任意のセルへ到達した場合も、翌日の計画を継続できます。経路はセル列を保存し、提出時だけ移動方向へ変換します。


## 得点と補給

種類の重複と在庫上限を考慮し、日別種類を玉数より強く評価します。当日の終端で補給車に届く燃料が残るかを評価し、翌日の行動余地を確保します。翌日がある場合、終了位置から別の店舗へ移動するための最少燃料を残せない車に減点を加え、少量の燃料を残したまま数日間動けなくなる計画を避けます。必要量は地形の燃料消費から正確に求め、現在いる店舗を除いて比較します。前日までの採用計画から取得済み種類を記録し、2日目以降に未取得の種類が残っていれば強く優先します。試験用の到達性重みが正の場合は、各ブランドについて終了位置から最も早く到達できる巡回車を求めます。最短移動時間に必要燃料の不足分を加えた見積もりが翌日のステップ数の4分の1を超える場合、その超過を軽く減点します。ただし、この見積もりを加えた短縮試験は悪化したため、既定では無効にしています。同じ回収数・到達性なら移動・待機が短い計画を優先します。最終日は得点以外の評価を0.01倍にし、終了時刻や経路未完了の小さな差より玉数を優先します。

補給車の位置を各ステップで再現し、巡回車の移動中・待機中の補給も計算します。燃料消費は移動が反映される直前、補給は移動後という公開規則の順序を守ります。途中までしか進めない移動は、巡回車・補給車とも実行できる命令までに切り詰めます。補給車は次の目的地へ到着できない日も途中まで進めます。巡回車の燃料が不足し、補給車が後で現在位置を通る場合は、補給を待って同じ経路の走行を再開する計画も評価します。

## 探索

当日の初期案には、前日の訪問列と補給地点を逆順にした候補も加えます。補給地点の到着待ちと出発待ちを入れ替え、出発時刻を当日の日内ステップ数へ合わせます。当日の開始位置・燃料・実際の道路状態で全経路を評価し、通常の初期案や引き継いだ翌日計画より良い候補を使って探索を始めます。

初期解では、各店舗を訪問列へ挿入する位置を比較します。その後、焼きなましで挿入、削除、交換、区間反転、担当変更、日を跨ぐ訪問移動、補給地点・出発時刻の変更を行います。2台の訪問列の後半を交換する操作と、連続する複数の訪問を別の車へ移す操作も使い、関連する店舗の担当をまとめて変更します。巡回車が3台以上なら、3台の訪問列の後半、または各車1箇所の訪問を循環交換する操作も使います。3台すべての変更後に採否を決め、途中の担当変更で回収種類が一時的に減る組み替えも探索します。補給地点の変更と巡回車の待ち合わせを同時に提案する操作も用います。当日探索では車1～2台の訪問列を空から組み直すビーム探索も行い、逐次の交換では抜けにくい配置から改善します。ビーム内の状態には、訪問列の終了時刻と、その時点の燃料を保持します。日末まで待機すると後で補給される場合も、経路を延ばす時点の燃料として区別します。同じ訪問済み店舗・終了位置について、評価値・時刻・燃料のいずれも改善できない候補を除き、探索枠を別の経路に使います。ビームへ残す途中候補の順位には、店舗数が少ないほど弱めた終了時刻の減点を加え、少数の回収のために長い時間を使う経路への偏りを抑えます。完成候補の採用は元の得点・燃料評価で判断します。

当日探索では、補給車の日程を固定した全巡回車の経路割り当ても試します。各車単独で回収する場合と、他車の現在経路を補完する場合の2通りで、幅96・最大18段のビーム探索を行います。経路延長の差分評価と重複経路モードの除外を使い、それぞれ回収店舗集合ごとの上位48本と現在経路を保存し、同じ回収集合なら評価の高い経路へ統合します。在庫数を店舗ごとの3ビットに詰めた整数と回収種類集合を使い、幅192のビームで車両間の組み合わせを探索します。未割当車の候補全体から得る店舗・種類の上限と、残り3台以下では各車が1経路を選ぶ場合の独立した増分上限を使います。元の評価器で改善した場合だけ採用し、時間切れの場合は元の計画を保持します。探索周期3・6・9の境界などで呼び出し、1回の予算は回答時間の2%以下、最大1秒とします。

既定の1台分ビーム探索では、既に計算した経路の終了位置・時刻・到着時燃料・回収店舗集合を保持し、経路を延ばす区間だけを再計算します。同じセル列になる経路モードは一つだけ評価します。日末までの待機で得る補給と、経路を延長する時点の燃料を区別します。旧評価器で最後に再評価し、改善した経路だけを採用します。開発用の翌日同時探索や到達性評価を指定した場合は従来のビーム評価を使います。短縮時間の診断では、この差分計算と元の評価器の終了位置・時刻・燃料・得点の一致を確認しています。

実行できない訪問列の後半は定期的に除き、探索が未実行部分の変更に偏ることを避けます。2台分の訪問を部分的に取り除き、挿入探索で修復する操作を併用します。補給日程・開始状態・訪問列が一致する車両の評価は再利用します。補給車の時刻別位置と待ち合わせ可能時間帯も、日程が完全一致する直近1件を再利用します。車種選択中の初日の経路グラフは、必要な補給候補がすでに含まれていれば共有します。途中で日を終えた補給車までの最少燃料距離は、必要になった地点について計算して保持します。翌日用計画の補給地点は実座標を保持して次の要求へ渡します。

公開モデルの上限である8台・256ステップに合わせ、評価時の車両状態と補給車の時刻別位置は固定長配列に保持します。焼きなましの次候補は確保済みの訪問列へ内容を書き戻し、採用時に現在案と作業領域を交換します。経路延長は前述の差分状態から計算し、未使用の翌日計画のコピーも省きます。

回答時間が2秒以上ある当日探索では、開始燃料が容量の3分の1未満で、補給車の開始位置まで自力で届かない車がいる場合、その車を最初に補給する日程を試します。補給車が日のステップ数の4分の3未満で到着できる車を対象にし、全巡回車の訪問列をまとめて空にしてビーム探索で再構築します。先に補給する車の経路を最初に組み、残りの車で未回収の種類・店舗を補います。全体を組み終えた値で採否を決めるため、補給日程だけを変えると一時的に得点を失う変更も試せます。通常の焼きなましと同じ温度で新しい配置へ移る一方、最良案は別に保持します。該当する低燃料車がいない場合は、既存の1～2台の探索を続けます。

焼きなましの冷却は探索時間を12区間に分けた経過率で進め、最良案への復帰もこの区間の境界に合わせます。途中で65536反復ごとに戻す方式から変更し、一度の冷却中は現在案を継続して変更します。常に別途保持する最良案を提出し、最後の20%は低温で改善します。経路再構築は通常の幅32を使います。

第4引数を正にした通常の計画要求では、探索時間の約75%を当日に使います。探索中の有力案を終了位置・燃料・新規取得種類で区別し、当日評価の高い最大24案を保持します。当日最良評価から120以内の候補から、終了状態の違いも考慮して最大8案を選びます。それぞれの終了位置と燃料から翌日の初期計画を作り、残り時間を等分して各巡回車のビーム探索で改善します。当日評価から終端燃料の近似評価を取り除いた値＋翌日評価×第4引数で比較し、採用した翌日計画を次の要求の初期候補へ渡します。翌日の交通は予測値なので、次の実要求では実際の交通を使って評価し直します。最終日、回答時間が短い場合、車種選択中には、この候補保存と再評価を行いません。


既定動作の小盤面では、翌日の種類数を確認するため、探索時間の80%を当日の探索へ使います。当日評価が最良から120以内で、当日最良案より種類数が少なくない候補から、終了位置と燃料の違いも考慮して最大4案を選びます。それぞれを公開エンジンのコピーで実行し、翌日の位置・燃料と候補ごとの交通予測を作ります。交通予測は前述の自チーム滞在数・他チームの最短経路木・観測交通区分を使います。残り時間を等分し、補給日程も変更する通常の焼きなましとビーム探索で翌日を計画します。当日評価＋翌日に取れる種類数×1000で比べ、翌日の種類数が同じなら当日評価の高い案を選びます。翌日の玉数をこの比較値へ加えないため、翌日の玉数予測だけを理由に当日の案を替えることはありません。選んだ翌日計画の補給地点を座標で引き継ぎ、次の実要求では実際の交通と燃料から再評価して初期案にします。試算は同じスレッドで順次行い、その中でさらに翌日比較を呼び出すことはありません。

車種選択では補給車候補ごとの初期計画を比較します。経路グラフと初期解の構築時間を測定し、追加の試算を始める前に必要時間を確保します。各候補への配分時間が十分なら補給車を固定して初日を独立して探索し、余裕に応じて2日目・3日目も試算します。初日評価＋2日目評価×0.5＋3日目評価×0.25で役割を比較します。試算では未取得種類への追加加点を無効にし、初日に取得できなかった種類が多い候補を優先する誤りを防ぎます。余裕が残れば選んだ候補の初日を追加探索します。時間が短い場合は初期比較の最良候補から探索し、補給車の担当も訪問列と一緒に交換します。探索は内部単一スレッドです。


## 提出前の検証

提出計画を共通エンジンの状態コピーで実行します。各車の終了位置・燃料と、日別種類・玉数の増分を独自モデルと照合します。翌日比較で採用した計画も、当日を実行した後のコピーと同じ予測交通で照合します。共通エンジンが当日の計画を不正と判定した場合は待機計画へ置き換え、翌日の計画が不正なら翌日キャッシュを破棄し、診断を標準エラーに残します。前の回答が却下された場合は、待機計画を適用して内部履歴を同期します。

翌日用グラフを同じノード番号で評価する経路では、当日グラフの目的地を同じ順序で渡します。初日グラフを再利用した場合に、引き継いだ補給候補の追加順序でノード番号がずれる不具合を再現テストで防いでいます。
