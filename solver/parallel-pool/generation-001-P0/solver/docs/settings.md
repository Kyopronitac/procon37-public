# 第1世代 P0 の設定

候補ルートで `PATH=/home/jikky/.cargo/bin:$PATH cargo build --release -p solver -j 2` を実行します。起動は `target/release/solver 0` です。第1引数は非負整数の探索seedで、省略時は0です。追加引数や環境変数は不要です。

ソルバの総スレッド数は制御1＋探索14の15です。標準ライブラリのスレッドを14本だけ起動します。探索・予測からの追加スレッド生成はありません。再びselectを受け取った場合も、既存の14探索を終了してから新しい探索を起動します。

通常要求では受信した制限時間の95%または180msを残す時間の短い方を制御側の期限とし、基準探索自身も余裕を残します。残り日数があり3.5秒以上なら、当日探索に残り時間の64%、翌日試算にその残りを割り当てます。店舗16以下で5.5秒以上の車種選択では最大3日分を試算します。大盤面の車種選択は2日分を比較します。110ms以下の要求は履歴を同期して即時に待機計画を返します。

探索島の設定、候補の比較方法、通信と履歴同期の詳細は[候補の設計と検証](parallel-generation-001.md)を参照してください。共通基準が利用していた翌日重み等の環境変数は、各探索ジョブの設定で上書きするため本候補では使用しません。
