# 操作と実行設定

## CUI

リポジトリルートから `cargo run --release -p game --` に続けて指定する。

```sh
run 30 --label '対戦・単一スレッド・フル30件'
run --seed 10 --format final --jobs 1 --label '対戦・再現'
generate --seed 10 --format final --output /tmp/problem.json
serve --port 8081
compare RUN_ID_A RUN_ID_B --baseline RUN_ID_A
compare RUN_ID_A RUN_ID_B --format final --json
export RUN_ID --output /tmp/match.zip
import /tmp/match.zip --label '別端末の結果'
```

`run` は `--config FILE`、`--solver FILE`、`-- ARGS...`、`--no-build`、`--jobs auto|N`、`--solver-parallel` / `--solver-serial`、`--time-limit-ms N` に対応する。`--no-build` は全員のビルドを省略する。`--solver` と `-- ARGS...` は対象のプレイヤー0だけに適用する。`--output-dir DIR` で保存先を変更できる。Ctrl+Cで中断すると完了ケースを保存し、実行中の5人全員のプロセスを終了する。

選択・各日の制限時間は単独テスタと同一で、ソルバ側の探索予算とは別。短縮確認は `--time-limit-ms`、本番に近い条件での評価は時間指定を省略して実行できる。比較結果には実際に使用した条件を添える。

同時試合数は `--jobs` で指定できる。自動では `max(1, CPU数 / 5)` を基準にし、対象か相手に内部並列の指定があれば1試合になる。試合は車種選択と全日程の制限時間の合計が長い順（同じならseed順）で開始し、空いた実行枠へ次を割り当てる。`--time-limit-ms` の指定も見積もりに反映する。5人は並行して回答するため、合計を5倍にはしない。CUI・GUI共通で、対象のseed集合は同じ。完了後の履歴はseed順に保存する。

件数は1〜10000（既定60）。[フルテスト](../../../README.md#テスト) は対象が単一スレッドなら30件を明示し、GUI・設定JSONでも件数を30にする。スケジュール作成時のメモリ確保を抑えるため、範囲外はビルドや履歴作成の前に拒否する。CUI・GUI・設定JSON・履歴からの再実行に共通で適用する。単一seedは引き続き0〜18446744073709551615を指定できる。

## 5枠の設定

[設定例](../config.example.json) をコピーして編集し、リポジトリルートで `cargo run --release -p game -- run --config tester/game/config.example.json` と実行できる。

GUIの「新しく実行」で対象と4枠の名前・実行コマンド・ビルド・内部並列を設定できる。同じ内容をJSONで保存して `--config` に渡せる。実行後は「ログ」から保存された設定を確認する。GUIサーバーの `/api/config` は既定の完全なJSONを返す。

共通項目は単独テスタと同じ。対戦固有項目は次のとおり。

| フィールド | 内容 |
| --- | --- |
| `mode` | `"game"`（CUI・サーバーは入口に応じて固定） |
| `targetName` | プレイヤー0の名前。省略時は「対象ソルバ」 |
| `solver` / `build` / `solverParallel` | プレイヤー0の設定 |
| `opponents` | 4要素固定。順にプレイヤー1〜4 |
| `opponents[].name` | 名前（1〜80文字） |
| `opponents[].solver` | `program`、`args`、`cwd`、`env` を持つコマンド |
| `opponents[].build` | 任意のビルドコマンド。`null` なら省略 |
| `opponents[].solverParallel` | 内部並列の有無 |
| `opponents[].version` | 実装バージョンの識別文字列。標準サンプルは取得元コミット・ソルバ名・対戦用調整版を含む文字列 |

コマンド例（サンプル1）：

```json
{"program":"target/release/game-sample-1","args":["0"],"cwd":"/absolute/path/procon37","env":{}}
```

同一のビルドコマンドは1バッチ内で一度だけ実行する。ビルドは並行させない。全ビルド後に各実行ファイルの内容識別情報を保存する。サンプルの乱数seedは `args` に記録される。

## GUI

- 結果一覧の「対戦順位」は、「プレイヤー別の平均順位」で5人の全体・1回戦・準決勝・決勝の平均順位を表示する。スコア合計と同じく形式を行に置き、各プレイヤーを列に並べ、「全体」の行を強調する。「対象ソルバ · 形式別の順位」は初期状態では折りたたみ、開くと対象の平均順位と1〜5位それぞれの回数を確認できる。平均順位は小さいほど上位。
- 順位の平均・回数は全員ACの完了試合のみが対象。同率順位は保存された順位をそのまま使い、全体平均は全対象試合から計算する（形式別平均の単純平均ではない）。対象試合がない場合は「—」。スコア合計やケース一覧の絞り込みとは集計範囲が異なる。
- 各試合は「対象の順位」列に色付きで表示し、「順位順」で並べ替えられる。同点は「同率」、AC以外は代替動作を含む「参考」と表示する。リプレイの5人のカードにも最終順位を表示する。
- 履歴一覧には対象の平均順位、比較画面には共通ACケースの平均順位・順位分布・基準との差を表示する。比較の形式選択に連動し、詳細には形式別の平均順位も表示する。
- 「新しく実行」で条件を入力し開始。「中断」で完了済みケースだけを残す。
- 履歴を選び、結果の「再生」で盤面へ移動。5人の色付きカードまたは選択欄で詳細対象を切り替える。
- 道路状態は全員共通。在庫・系列・車両・ログは選択中のプレイヤーに対応する。全巡回車・補給車の当日全体の経路を参照ページと同じ点線で表示し、日付が変わると更新する。「他の4人も重ねて表示」で相手の車両と経路も表示する。
- 再生・日付・ステップ・速度・道路・系列の表示設定は単独テスタと共通。URL/ブラウザの戻る操作にプレイヤー選択も保存される。
- 「ヒートマップ」で各セルの巡回車・補給車の延べ滞在ステップ数を合算し、セル内の数字を表示せず対数スケールの色の濃淡で示す。通常盤面の道路状況は外枠の色で表示し、ヒートマップには枠線を表示しない。合計／車種別、当日／全日、選択チーム／全チームを切り替えられる。詳しい集計方法は[単独テスタの画面説明](../../solo/docs/gui.md#滞在時間のヒートマップ)を参照。
- 「GIF出力」は選択した日付範囲・速度と現在の表示設定を使う。選択プレイヤーと、表示を有効にした他チームの車両を含む。
- 「ログ」で設定JSONと個別stderrを確認。「JSON保存」は5人全員を含むリプレイを保存する。
- 「この設定で再実行」は新しい履歴を作る。インポート履歴のコマンドはローカルの既定値で置き換わる。
- 履歴の比較・削除・ZIP入出力、問題生成も単独テスタと同じ操作で利用する。

保存済みの問題・提出回答・全ステップを使って再生するため、閲覧にソルバの再実行は不要。

## 非公式練習場の取り込みケース

生成器v24は、取り込みを有効にすると `seed % 4 == 3` に非公式練習場の盤面を挿入する。各サイズ5枚を用意し、既存の #937・#941・#916 を先頭に、追加分はサイズ別に固定シャッフルしている。自動形式のseed 0〜59では15枚を各1回使用し、0〜29では7枚を含む。取り込み盤面の選択は60 seed周期。形式指定時はそのサイズの盤面を `floor(seed / 12) % 5` で選ぶため、同じ12 seed区間内では繰り返す。出典・使用順・参加人数の違いは [取り込みケース](../../../common/fixtures/arena/README.md) を参照。

### 取り込みの切り替え

既定は「含める」。CUIでは `--arena-maps` で有効、`--no-arena-maps` で無効にする。`run`・`generate`・`serve` で使え、`--config` の `"arenaMaps": true` / `false` よりコマンドライン指定が優先される。無効にすると取り込み対象のseedにも通常の生成マップを使う。公式サンプル3件は引き続き利用する。

GUIでは「新しく実行」と「問題を生成」の「非公式練習場のマップを含める（4ケースに1ケース）」で切り替える。`serve --no-arena-maps` は初期値をオフにする。設定は履歴に保存し、「この設定で再実行」へ引き継ぐ。保存済みの問題・リプレイは変更しない。

```sh
# 通常の生成マップで問題を確認
cargo run --release -p game -- generate --seed 3 --no-arena-maps --output /tmp/problem.json

# 練習場を含めるGUI（既定）
cargo run --release -p game -- serve --arena-maps
```

比較する実行は取り込み設定も揃える。設定が異なる場合、同じseedでも問題が変わるケースは比較対象から除外される。
