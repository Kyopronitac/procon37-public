# 保存形式・比較・ZIP

既定の `.game/runs/<実行ID>/` に保存する。単独テスタの履歴とは分離する。

```text
<実行ID>/
├── run.json
├── build.stdout.log
├── build.stderr.log
└── <seed>/
    ├── problem.json
    ├── replay.json
    ├── stderr.log          # プレイヤー0
    ├── stderr-1.log
    ├── stderr-2.log
    ├── stderr-3.log
    └── stderr-4.log
```

## JSON

`run.json` は共通のschema 3に `config.mode = "game"` を持つ。設定には5枠の名前・実行条件、サンプルのバージョンとseed引数を記録する。`opponentIdentities` はビルド後の相手4枠の実装識別情報。各ケースの `players` は5要素で、`id`、`name`、`rank`、`score`、`status`、`answerTimeMs`、`warnings` を保存する。ケース最上位の得点は対象ソルバ、判定は全員の最も重い判定（TLE→RE→WA→AC）。

`replay.json` は **schema 2**。最上位がプレイヤー0、`opponents` の4要素がプレイヤー1〜4。それぞれに問題、車種選択の提出回答・採否・時間、各日の提出回答・採否・適用計画・道路・全ステップの車両と在庫・イベント・得点を保持する。相手要素の内部構造は単独リプレイschema 1と同じだが、問題の `players` は5。対戦リプレイは全体で1つの記録として扱い、相手要素だけを単独テスタへ渡さない。

既存テスタの履歴はschema 1リプレイを継続し、移行は不要。

## 比較

2〜4履歴を比較できる。対象の3指標合計、基準に対する勝・同点・敗、順位分布と各対戦相手への勝・同点・敗を表示する。全体と形式別に集計する。

順位は対象ソルバと5人それぞれの平均も計算する。比較JSONの各scopeの `game.averageRank` が対象の平均順位、`game.playerAverageRanks` がプレイヤー0〜4の平均順位。対象試合がない場合は `null`。平均は各試合の保存順位（同率を含む）の合計を対象試合数で割り、画面とCUIでは小数第2位まで表示する。保存済みの順位から集計するため、既存履歴の変換やソルバの再実行は不要。

集計対象は、同一問題・同一形式で、比較するすべての履歴の5人全員がAC、相手4枠の実装識別情報と制限時間が一致するケース。欠落・異なる問題や相手条件・非ACのケースは除外する。対象ソルバの変更は比較を妨げない。

相手の識別情報は名前・バージョン・コマンド・引数・cwd・明示環境変数・主要な継承環境変数と、実行ファイルおよびファイル引数の内容から作る。外部サービスや実行時に別途読み込むファイルまで検出する保証はないため、そのような相手では `version` を更新する。識別値は内容比較用であり署名・改ざん防止の証明ではない。

ビルドコマンドとケース並列数の選択用フラグ `solverParallel` は識別情報に含めない。同じ相手の実行条件とファイル内容なら、通常ビルドした履歴と `--no-build` の履歴を比較できる。
各ファイルはパスと内容の長さを付けてから内容を取り込む。複数ファイルの連結結果が同じでも、ファイル間で内容が移動した場合は別の識別値になる。
この方式の識別値は `content-v3:` で始まる。以前の `content-v1:`・`content-v2:` の履歴はそのまま保存し、新方式の履歴と混ぜると相手条件不一致として除外する。過去の実行ファイルを現在のものとして再計算・上書きすることはしない。

## ZIP

ZIPの識別子は `procon37-game-run`。単独テスタの `procon37-run` と混同せず、入口と形式が一致しない取り込みを拒否する。既存の安全なZIP処理を共有し、パストラバーサル・重複エントリ・リンク・不明ファイル・サイズ超過を拒否する。圧縮ZIPは256MiB、展開後全体は1GiB、1ファイルは64MiBまで。

インポート時に5人の保存計画を共通エンジンで再実行し、各フレーム、在庫、交通量、得点、採否、順位を照合する。ソルバのプログラムは実行しない。検証成功後だけ新しいIDで保存する。

取り込んだ実行コマンド・ビルドコマンド・環境変数・内部並列設定は5枠ともローカルの既定値へ置き換える。名前と過去の結果・実装識別情報は残し、元履歴との比較は可能。取り込んだ履歴を再実行すると、その時点でのローカル実装の識別情報を新しく記録する。
