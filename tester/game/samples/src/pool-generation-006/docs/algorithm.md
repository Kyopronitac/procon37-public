# 第6世代ソルバの設計

このソルバは公開通信仕様と共通エンジンの規則から新規に実装した、内部単一スレッドのソルバである。相手ソルバと保存版の内部実装は使用していない。

## 経路と車種

店舗、初期位置、通行可能なセルから格子状に選んだ地点を中継点とする。各点の間に4種類の経路を作る。移動時間優先、時間と燃料の加重和、燃料優先、同じ最短時間の範囲で店舗経由を優先する経路を逆向きDijkstra法で求める。各経路には所要時間、燃料、通過店舗、中継点にいる時間区間を保存する。当日の道路コストは受信した交通状態から計算する。各中継点から最寄りの別店舗への時間・必要燃料と、全店舗への最速時間・その経路群の最大必要燃料も経路表構築時に保存する。最寄りの別店舗へ直接届く燃料がある場合は移動遅延をゼロとし、全店舗へ直接届く場合は保存した時間表を使って到達評価の再計算を省く。

車種選択では、各車両を補給車にした構成で初日の探索を行い、上位2構成を追加探索する。さらに各構成の初日を共通エンジンで実行し、その終了状態から翌日の巡回も短く探索して比較する。全日程の最大燃料消費を初期燃料だけで賄える場合は、全車巡回も比較に加える。

## 補給と巡回

巡回車の計画は、訪問店舗、補給待機、補給地点への合流を表す列で持つ。移動経路の種類は車両全体と個別の区間で変更できる。移動時間または燃料で実行できない訪問は飛ばし、実行可能な残りの訪問を試す。

補給車には次の計画方法を用意する。

- 指定した店舗を移動し、各地点で待つ。
- 巡回車の予定経路から合流できる時刻を列挙し、燃料不足の解消量と移動時間を見て合流先を選ぶ。
- 合流の地点・時刻を固定し、巡回車の経路を改めて最適化する。

補給判定は経路上の全マスで行い、到着時だけでなく移動の反映待ちや待機中の重なりも評価する。経路選択用の中継点以外で起きる接触補給も燃料へ反映する。巡回車が動き出す前に補給車を待つ候補も扱う。合流地点・時刻・順序を直接変更する近傍を持つ。当日の固定補給予定に立ち寄りを追加する際は、4回に3回、現在の巡回計画が中継点を占有する時間帯から地点と時刻を選ぶ。元の無作為な追加も残し、変更後の巡回と補給を全体評価で再計算する。燃料消費が補給より先に行われる順序を守る。

固定された補給予定は開始地点・日長・合流予定列で照合し、全マスの滞在時刻と提出行動列を再利用する。自動補給は合流予定を生成し、固定予定と同じ経路構築処理を使用する。交通状態の更新時にこの記録を消す。

同じ補給予定・移動経路・出発時刻の燃料計算も再利用する。最初の補給地点へ届くための必要燃料と、最後の補給後に残る燃料を求めることで、開始燃料が違う候補にも同じ計算結果を使える。補給間の消費が燃料上限を超える場合は到達不可として扱う。

車両ごとの巡回評価も再利用する。補給予定の識別子、開始位置と燃料、日長、出発待機、経路種別、自動補給の設定、巡回列がすべて一致したとき、回収店舗・終了位置・燃料・終了時刻・無効訪問の罰則を読み出す。直近の車両評価を先に照合し、一致した場合は巡回列のハッシュ計算も省く。一致しなければハッシュ表を調べる。ハッシュ値だけでは一致とみなさず、巡回列そのものも確認する。キャッシュが当たった4096回に1回は再計算して結果を照合する。提出行動の生成は直接計算で行う。

## 日別探索

日別探索は当日の種類数と玉数を中心に評価する。最終日以外では、終了時の燃料残量、補給車までの距離、店舗を車両がどの程度分担しているかを補助点として用いる。目標残燃料からの不足には線形の罰則を使う。翌日の店舗への到達見込みでは、手持ちの燃料で直接向かう経路、現在位置で補給車を待つ経路、補給車の位置まで移動する経路を比べる。目標残燃料からの不足を除く補助点には0.1倍の係数を掛け、当日の回収を優先する。燃料不足の罰則は元の強さに保ち、翌朝の燃料枯渇を抑える。同等の回収数なら短い巡回を好む小さな補助点も持つ。

各日末には、車両ごとに翌日の最初の別店舗へ着く時間を見積もる。燃料制約と補給待ちを考慮した最短到達時間から、燃料制約なしの最短時間を引く。翌日長の1/8までは許容し、それを超える遅延を1ステップにつき8点の罰則とする。店舗ごとの最寄り車だけを見る評価で、他車の陰に隠れてしまう動けない車両を抑えるための補助点である。共同探索では当日末・翌日末の両方に、その日の割引率で適用する。

まず1日分を最適化する。非最終日は、通常の補助点で得た当日候補と、余剰燃料・配置の補助点を強めて得た候補を用意する。各候補の終了状態から翌日を試行し、当日の得点と翌日の予測得点を比較する。翌日の日別種類数・玉数の重みは当日の0.8倍とし、全期間の種類数は2日分の和集合で評価する。

翌日試行では、自チームの直近の滞在と当日候補の模擬滞在を使って道路状態を予測する。対戦時は滞在数を0.8倍とする。道路混雑が蓄積する初期2日間だけは、現在の観測より軽い混雑にはしない。3日目以降は古い滞在が集計対象から外れるため、混雑が軽くなる予測も許す。これは他チームの経路が自分と異なることを考慮した近似である。予測用の経路表へ切り替える際には交通に依存する補給経路・到達評価のキャッシュを消し、試行後に当日の経路表を戻す。両候補の巡回列と逆順を共通の初期候補にし、同じ乱数状態・同程度の時間枠で探索する。経路表の構築と翌日初期化も各候補の時間枠に含め、先の候補だけに探索時間が偏らないようにする。選んだ翌日計画は次の観測まで保持し、実際の交通状態と燃料を受信した後に最適化し直す。前日に改善した訪問列、その逆順、補給予定を再計算した列も初期候補として比較する。

探索は以下を組み合わせる。

- 焼きなまし：訪問の追加・削除・交換・逆順化、車両間の移動と経路後半の交換、補給計画や経路の種類の変更。訪問の挿入ではランダムな位置と移動増分が小さい位置を併用する。
- 経路の再構築：一部または全車の巡回を取り除き、追加時間に対する得点増分で訪問を挿入する。全車の再構築と一部の局所再構築では補給予定も再生成し、担当分けと合流位置を同時に変える。再構築には個別の時間枠と累積35%の上限を設け、残りを焼きなましやビーム探索へ残す。
- ビーム探索：他車の回収と補給時刻を固定し、1台の訪問順を探索する。幅は与えた時間に応じて1024、2048、8192とする。各移動区間で4種類の経路を比較する。同じ位置・訪問集合について、遅く燃料も少ない状態を除く。訪問数の上限は店舗数に合わせ、期限までに得た途中候補も比較する。
- 2台の再構築：開始位置の近い巡回車2台の訪問列をいったん空にし、交互にビーム探索して担当分けを作り直す。

1日分の探索では、全体探索の後に各巡回車へビーム探索の時間を配分し、余った時間は全体探索に戻す。非最終日で残り2秒超の場合は、通常の当日候補に48%、補助点を強めた候補に12%、翌日試行による比較に20%、選んだ当日・翌日の共同探索に20%を割り当てる。2秒以下では共同探索を省き、60%・15%・25%とする。共同探索は2日の巡回と補給予定を変更し、当日の終了位置と燃料が翌日の回収へ及ぼす影響を直接評価する。翌日の道路状態は比較時に選んだ予測で固定し、当日の変更ごとの道路再予測は行わない。当日と翌日の経路表は同じ中継点番号を持ち、補給予定と到達評価のキャッシュは両者を区別する。2日後の燃料・配置補助点は通常の0.1倍とする。最終日は末尾の待機を移動へ置き換える候補を共通エンジンで直接比較する。待機開始直後と待機中の補給直後を出発候補にし、当日の得点が厳密に増える場合だけ採用する。

ビームの各深さで64候補を残し、燃料や配置を含む全体評価で比較する。翌日への到達見込みは、巡回車の位置・燃料・補給車の位置・翌日の長さをキーとして一部を再利用する。交通状態を受信した際にこの記録を消す。

最後に共通エンジンで提出計画を検証する。末尾の追加移動を試す前に、予測した終了位置と燃料も全日について共通エンジンの結果と照合する。共同探索では予測した翌日の交通を使った2日分の終了状態も別に照合する。これは予測交通の正しさではなく、内部モデルと共通エンジンの整合性を確認する。検証に失敗した場合はその日の全車待機を返し、stderrに理由を残す。次の観測では前日の実行結果と受信した車両状態・交通状態を反映する。

## 実装

- `main.rs`：JSON Linesの要求・回答と時間管理。
- `solver/planner.rs`：経路表、車種選択、補給、巡回探索、提出前検証。

スレッド作成、他ホストへの通信、分散探索は行わない。
