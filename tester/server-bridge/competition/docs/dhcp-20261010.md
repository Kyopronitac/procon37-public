# 本番LANへのDHCP移行（2026年10月10日）

VOIDLINUX-1・2・3の有線プロファイルをIPv4 DHCP自動取得へ変更し、固定アドレス・固定ゲートウェイ・固定DNSを削除した。使用中のプロファイルだけを自動接続し、古い予備プロファイルから固定IPが復活しないよう予備もDHCPへ変更した。

| PC | 有線インターフェース | 内部通信名 |
| --- | --- | --- |
| VOID1 | enp3s0 | voidlinux-1.local |
| VOID2 | enp4s0 | voidlinux-2.local |
| VOID3 | enp3s0 | voidlinux-3.local |

各PCに公式署名を検証したAvahi・nss-mdns・libdaemonを追加した。Avahiは有線インターフェースだけでIPv4名解決を提供する。SSHはPC名を使い、ソルバの待受け・接続には起動時に解決したIPv4を渡す。固定されたリリース設定を書き換えず、IP変更に追従する。試合中にLANを切り替えた場合は停止・再起動する。

移行時の作業LANにはDHCPサーバーがなかったため、DHCP取得を継続しながら自動リンクローカルアドレスで3台の通信を確認した。会場LANへつなぐとDHCPでアドレスを取得する。移行時点では会場でのリース取得および `172.28.0.10:8080` への疎通は未確認だった。移行時のLANでの `/setting` GETは経路なしだった。DHCP待ちの間はNetworkManagerが「接続中」と表示する場合がある。

検証では3台のmanifest・CPU・認証ファイル権限を照合し、固定IP除去後のPC名によるSSHログイン、両workerのTCP認証、coordinatorの起動と終了を確認した。Solve要求・回答提出は送信していない。確認後は3台とも停止し、残存プロセスがない状態に戻した。

ローカル検証はcompetition運用テスト13件と、3種類の起動モードの引数受け渡し確認が成功した。既存のserver-bridge運用テスト35件には2件の失敗・1件のスキップがあり、変更前のHEADでも同じ2件が失敗することを確認した。失敗はconsole経由の起動出力に対する古いテスト期待値で、今回のDHCP変更による増加はない。

## 会場の接続テストでの確認

3台が会場のDHCPからアドレスを取得した。VOID1は `172.28.3.51/16`、VOID2は `172.28.3.69/16`、VOID3は `172.28.3.71/16`。アドレスは固定値ではなく、起動時は引き続きPC名で解決する。

会場DNSへの `.local` 判定が約10秒待ちになり、worker起動確認がタイムアウトしたため、3台の `/etc/nsswitch.conf` のhosts行を `files mdns4 dns` にし、`/etc/mdns.allow` に `.local.` と `.local` を指定した。mDNSだけで対象名を解決することを明示し、解決時間は2〜3ミリ秒へ改善した。

公式 `/setting` と `/` は指定トークンのクエリ付与でHTTP 200を確認した。実際の接続テストは16×16、`daySeconds=[20,20,20,20]`、`daySteps=[64,64,64,64]`、60チームだった。

最初の1試合では4日とも回答が受理されたが、VOID1の時計が約1.02秒遅れていたため19.5秒時点の再提出は拒否された。試合間に3台を停止し、NTP同期済みの作業PCの時計に合わせた。補正後の往復遅延を考慮した差はVOID1が約−9ms、VOID2が約−16ms、VOID3が約−4ms。補正後は19.5秒の再提出も受理された。競技サーバーとゲートウェイへのNTP照会には応答がなく、今回の時計補正は継続的なNTP同期の確立を意味しない。

時計補正後、車種選択から4日目まで通した接続テスト1試合が完了した。車種選択と4日すべてが受理され、実送信は計7回受理・0回拒否。同一回答の再送は既定どおり省略された。全5要求でVOID1は `local_completed=31/31 remote_results=2/2`、VOID2は15/15、VOID3は31/31の探索完了を確認した。確認後は3台を停止した。VOID1の `.server/connection-test-20261010.json` に集計を保存し、完全ログは選択リリースの `logs/20261010T012808.688906Z-3944.log` にある（時計補正後の途中参加分と通し1試合を含む）。

## 3台の無線機能をOFF

VOID1・VOID2・VOID3で `nmcli radio all off` と `rfkill block all` を実行し、Wi-Fi・Bluetoothの全デバイスが `Soft blocked: yes` であることを確認した。有線SSH接続は維持した。NetworkManagerは `WirelessEnabled=false`、`WWANEnabled=false` を保存し、各PCの `/etc/udev/rules.d/90-procon37-radios-off.rules` で起動時・無線デバイス追加時にも全無線をブロックする。再起動は行っていない。
