# GUIで視覚確認

以下のコマンドは対象チェックアウトのルートで実行するgameの例。soloでは `-p game` を `-p tester` に置き換える。


盤面配置、車の経路、補給、混雑の変化、特定の日・ステップの状態、GIF出力を確認するときに使う。得点集計や通常のバッチ実行だけならCUIで完結させる。

## サーバーを起動する

```sh
# Linux / WSL / macOS共通。表示されたURLをブラウザで開く
cargo run --release -p game -- serve
```

フルテストの履歴は既定の保存先で開く。フルテスト以外は `serve --output-dir "$procon37_test_dir" --port 0` で一時保存先の記録を開くか、既存GUIの「JSONファイルを開く」でリプレイを一時閲覧する。通常の履歴へインポートする必要はない。既存サーバーを使うときは、対象チェックアウトと保存先が一致することを確認する。
Linux / WSLの登録済みコマンドは対戦が `game --no-open`、単独が `solo --no-open` で起動できるが、別のチェックアウトを指すことがあるため、対象が不明なら上のCargoコマンドを使う。

## リプレイを確認する

- CUIの実行IDに対応する履歴を選び、対象seedの「再生」を開く。保存済みリプレイを見るための再実行は不要。
- 対戦ではプレイヤー選択で車両・在庫・経路・ログを切り替え、他チームの重ね表示も選べる。
- 日付・再生バー・左右キーで対象時点へ移動し、「詳細」で車・出来事・設定を確認する。
- 盤面だけなら「問題を生成して見る」、保存済みの問題・リプレイなら「JSONファイルを開く」を使う。
- 「新しく実行」と「問題を生成」の「非公式練習場のマップを含める」で取り込みを切り替える。既定はオンで、4 seedに1件含む。オフでは取り込み対象のseedも通常の生成マップになる。再実行は保存した設定を引き継ぐ。CUIとJSONの指定は [実行手順](run.md#非公式練習場のマップを切り替える) を参照する。
- ブラウザ操作ツールが利用できる場合はその仕様に従って操作する。利用できない場合も、CUIの結果と保存JSONから確認できる内容は先に調べる。
- テスタ・生成器・画面を変更した後は、サーバーを再ビルド・再起動し、ブラウザを再読み込みする。保存済み履歴は当時の問題を保持するため、新しい生成器の確認には新しいプレビューを使う。
