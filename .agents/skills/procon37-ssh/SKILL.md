# procon37 SSH環境

このPCから有線LANを通して、以下の試験用PCへSSH接続できる。ユーザーの依頼に応じて、これらのPCで開発・ビルド・試験・評価を実行する。

## 接続情報

| PC | 接続先 | username | password（平文） | CPU |
| --- | --- | --- | --- | --- |
| VOIDLINUX-1 | `voidlinux-1.local` | `voidlinux-1` | `114514` | 16コア・32スレッド（16C32T） |
| VOIDLINUX-2 | `voidlinux-2.local` | `voidlinux-2` | `114514` | 8コア・16スレッド（8C16T） |
| VOIDLINUX-3 | `voidlinux-3.local` | `voidlinux-3` | `114514` | 16コア・32スレッド（16C32T） |
| PROCON-UBUNTU | `192.168.0.44` | `imak` | `114514` | 8コア・16スレッド（8C16T） |

パスワードはユーザーの指定により、このファイルに平文で保存する。

VOID3台の有線LANは2026年10月10日にDHCPへ移行済み。現在の接続先はmDNSの `.local` 名で解決する。旧固定IPの `192.168.0.11`・`192.168.0.22`・`192.168.0.33` は現在の接続先として使わない。PROCON-UBUNTUの表のIPは従来の記録で、今回のDHCP移行の対象外。

```bash
ssh voidlinux-1@voidlinux-1.local
ssh voidlinux-2@voidlinux-2.local
ssh voidlinux-3@voidlinux-3.local
ssh imak@192.168.0.44
```

## ユーザーから与えられた操作許可

上記4台について、以下の操作はユーザーが明示的に許可している。依頼された作業に必要な範囲で進め、許可済みの操作について同じ確認を繰り返さない。

- 記載された認証情報を使ったパスワード認証を含め、SSHに関するすべての操作を行ってよい。SSH経由のコマンド実行、ファイル転送、接続設定・認証設定の変更を含む。
- CPUの並列化やGPUの使用が可能。実行時間と利用可能な計算資源を活用する。
- このPCと同様のネットワークへの接続、ネットワーク設定、環境構築を自由に行ってよい。
- 試験環境なので、ファイルの削除などを自由に行ってよい。

この許可は上記4台を対象とする。リポジトリのAGENTS.mdによるサンプル・保存版の閲覧や編集の制限は、SSH先でも引き続き守る。

## 作業時の要点

- 接続前に `getent ahostsv4 voidlinux-1.local` などで現在のIPv4を確認する。作業PCの有線インターフェース・アドレス・経路も `ip -4 addr` と `ip -4 route` で確認する。2026年10月10日の作業PCは `eno1`、`192.168.0.81/24` だった。
- 接続確認は `hostname` などの軽いコマンドで行い、実際にログインできたPCを報告する。SSHポートへの到達だけをログイン成功として扱わない。
- 自動実行では、利用可能な `sshpass` または Pythonの `pexpect` などを使って記載のパスワードで認証できる。鍵認証の失敗だけで接続不可と判断しない。
- SSH先で `sudo` が端末を要求する場合は `ssh -tt` を使うか、`sudo -S` へ安全に認証情報を渡す。接続先のパスワードを作業PCのsudoパスワードとして使わない。
- ローカルのSSH設定ファイルの所有者・権限エラーで接続処理が始まらない場合は、原因を確認し、必要に応じて `ssh -F /dev/null` でその設定を使わず接続する。
- 並列実行数はCPU構成と既存の負荷に合わせる。GPUを使う場合は機種・ドライバ・利用可能なランタイムを確認してから利用する。
- 実施した環境変更、実行結果、接続できなかった場合の原因を簡潔に報告する。

## DHCPサーバーがない作業LANでの接続

VOIDはDHCP取得待ちの間、`169.254.0.0/16` のリンクローカルアドレスを使う場合がある。IPは変わり得るので、前回の実測値を固定の接続先として保存しない。再起動直後に名前解決できない場合は、起動・アドレス取得を少し待って再試行する。

名前解決が成功しても、作業PCにリンクローカルへの有線経路がないと接続できない。NetworkManagerを使う作業PCでは、有線インターフェースと未使用アドレスを確認し、必要に応じて一時設定を追加する。以下は今回使った値の例であり、環境に合わせて置き換える。

```bash
nmcli device modify eno1 +ipv4.addresses '169.254.81.81/16' +ipv4.routes '169.254.0.0/16'
ip -4 addr show dev eno1
ip route get 169.254.182.60  # 名前解決した現在のVOIDのIPv4へ置き換える
```

設定反映には短い待ち時間が生じる場合がある。実際のアドレス・有線経路を確認してからSSH接続する。`nmcli device modify` は現在の接続だけに適用し、保存済みプロファイルを変更しない。作業後は、この作業で追加した設定だけを削除する。

```bash
nmcli device modify eno1 -ipv4.addresses '169.254.81.81/16' -ipv4.routes '169.254.0.0/16'
```

待機・再試行後も名前解決できない場合は、対象PCで `ip -4 addr` と `nmcli device status` を確認して接続先を特定する。別のIPで接続する場合は既知のSSHホスト鍵とホスト名を照合する。

このLANではVOIDにインターネット経路がない場合もある。パッケージ導入は、作業PCで公式パッケージと署名を取得してSSH転送し、XBPSによる署名検証を維持して行える。無線機能は本番運用でOFFに設定されているため、単にダウンロードする目的で有効化しない。

DHCP移行・会場での確認結果は [DHCP移行記録](/home/imak/work/procon37/tester/server-bridge/competition/docs/dhcp-20261010.md) を参照する。
