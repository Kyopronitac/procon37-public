# ソルバの世代育成

目的は、多様な強いsolverを5体揃えること。親agentが評価・配置替え・昇格・commit・pushを担当し、開発subagentが新規設計と改善を担当する。開発方法は開発者の判断に任せる。

「`$procon37-solver-pool` で3世代育成して」のように実行する。世代数が未指定なら確認する。skillの作成・編集依頼だけでは育成を開始しない。

## モデル

特別な指定がなければ、親agentは **GPT-6 Sol / medium**、開発subagentは **GPT-6 Astra / xhigh** を使う。親のモデルは実行するchat側で選択し、このskillによる自動切り替えは行わない。

開発者の起動時は `model="gpt-6-astra"`、`reasoning_effort="xhigh"` を明示する。ユーザーが別のモデル・推論設定を指定した場合はそちらを優先する。

## 役割とコンテキスト

- 各世代の開発者を `collaboration.spawn_agent` の `fork_turns="none"` で新規起動する。親の会話や前世代の開発履歴を継承させない。同じ世代の改善は同じ開発者が続ける。
- [開発依頼](docs/developer-task.md) には、作業場所・公開仕様・編集範囲・対戦設定・評価条件と必要な結果だけを渡す。親への報告も方針・変更範囲・実験結果の要点に絞る。
- ファイルは共有されるため、履歴なし起動だけでは隔離されない。旧実装・他世代の設計資料を開発者に参照させない。サンプルは [閲覧規則](../../../tester/game/samples/AGENTS.md) に従うブラックボックスであり、コピーやGit履歴を含む実装閲覧・検索・逆解析をしない。
- 開発者は対象solverとその資料を編集する。sample・対戦設定・採点器の変更やGit操作は開発作業に含めない。

## 指定世代数だけ繰り返す

1. **評価・配置替え。** 現在の5体をgameのフルテストで評価し、平均順位最下位を `main.rs` 側、残り4体を `tester/game/samples/` に配置する。同率最下位は固定ID順で選ぶ。識別情報と条件が一致する既存結果は再利用してよい。
2. **最下位を削除。** 対象の実装を削除する。開発者に旧実装を引き継がず、0からソルバを作成する。
3. **単独首位まで開発。** 開発者が実装・実験・改善を進め、親が候補を正式評価して他4体と平均順位を比較する。未達なら結果を開発者に返し、単独首位になるまで継続する。設計や実験のたびにユーザーの確認を求めない。
4. **昇格・commit・push。** 親が保存結果から昇格条件を確認し、評価した実装と記録をcommit・pushする。push成功までを1世代と数え、その5体で次世代へ進む。

配置替え・削除は `main.rs` だけでなく専用モジュール・設定・依存を含む実装一式を対象とする。残す4体は対象側の変更から独立してビルドでき、ソースから再現できる状態に保つ。移動のために相手のアルゴリズムを読む必要はない。

## 開発テストと昇格条件

**開発中の短縮テストは自由に実行してよい。** 開発者が件数・seed・制限時間・探索予算・試行回数を選び、必要に応じて繰り返す。短縮テストに親やユーザーの事前確認は不要。操作と保存先は [procon37-tester](../procon37-tester/SKILL.md) に従う。

正式な昇格判定には [プロジェクトのフルテスト定義](../../../README.md#テスト) を使う。特段の指定がなければソルバは単一スレッドとして扱い、gameは30件（seed 0〜29）・形式自動・既定制限時間・既定保存先で評価する。

- 規定の全試合で5体全員がACであり、対象の平均順位が他4体すべてより厳密に小さいこと。**同率首位は不可。** 欠落・非ACを除外して達成扱いにしない。
- 平均順位は保存された各試合の順位から計算する。丸めた表示値ではなく順位合計で比較する。
- 正式評価では相手4体と評価条件を固定し、評価中の候補も変更しない。短縮結果は昇格判定に使わない。
- 過去の成績との比較には手順1の記録を利用し、相手配置や実行条件が異なる場合はその違いを明記する。削除前に比較専用の追加テストは行わない。

フルテストの監視・待機はtester skillに従い、親が再開を管理する。開発者と正式評価を重複起動しない。

## 記録と完了

各世代の5体の対応、実装の識別情報、評価条件・実行ID・平均順位、前後比較、commit・push結果を `solver/docs/solver-pool-experiment/records/` に残す。開発者へは管理記録全体を渡さない。

再開に必要な世代・段階・実行・開発者・push済み状態を `.game/pool-state.json` に記録し、再開時は実状態と照合する。ユーザーの変更を保ち、今回の変更のみをリポジトリの規約に従ってcommit・通常pushする。

指定数のpush完了が終了条件。未達や失敗を成功として数えず、停止指示・予算上限・解消できない障害では状態と再開に必要な事項を報告する。終了報告は完了世代数、順位、commit・push結果、記録先を中心に簡潔にまとめる。
